# 【架构分工与防覆盖声明（ADR-0061 / 抓取与索引分离机制）】
# 本文件（robots.txt）与 public/_headers 各司其职，严禁混淆：
# 1. robots.txt 仅负责「抓取权限（FETCH）」：全量放行（Allow: /），绝不写任何 Disallow。
# 2. _headers 负责「索引控制（INDEXING）」：对非内容资产（/install*, /schemas/*, /api/*）
#    统一由响应头下发 `X-Robots-Tag: noindex, nofollow` 显式阻止索引。
# 爬虫必须先被允许抓取（robots.txt Allow），才能在 HTTP 响应中读取到 noindex 指令！
# 若在 robots.txt 中使用 Disallow，爬虫将永远无法探测到 noindex 头，反而导致外部链接
# 以无标题空壳形式被强行收录，产生两套机制互相矛盾的严重缺陷。任何维护者切勿在此添加 Disallow 行！
#

# 核心论证一：为什么对所有 AI 与搜索引擎爬虫一律显式放行？（STANCE ON AI CRAWLERS）
# ------------------------------------------------------------------------
# 传统站点封禁 GPTBot/ClaudeBot/PerplexityBot 等是担心自身内容被抓去训练形成竞争。
# 这一逻辑在无极开物（Kaiwu）完全反转：
# 1. 真实用户在向大模型提问：“Claude Code / 智能体开发有什么好用的客户端与工作台？”
#    AI 助手的答案直接来自其索引库与检索生成（RAG/Grounding）。封禁 AI 爬虫等于主动放弃
#    开物最核心、最高意图的获客转化渠道。
# 2. 开物 100% 开源（MIT 协议），源码完全公开于 GitHub。爬虫在此处获取不到任何无法从仓库
#    直接 clone 的私有信息，根本不存在需要封锁的护城河。
#
# ------------------------------------------------------------------------
# 核心论证二：为什么一条 Disallow 都不写？为什么 noindex 才是唯一正解？
# ------------------------------------------------------------------------
# /install.sh 与 /install.ps1 是脚本程序，/schemas/ 是规范元数据，/api/ 是服务接口，
# 都不应作为普通网页搜索结果呈现。很多维护者的下意识反应是在 robots.txt 中 Disallow 它们。
# 这是 SEO/GEO 领域最常见、危害最大的高频误区：
#   Disallow 只能阻断抓取（FETCH），无法阻断索引（INDEXING）。
#   当搜索引擎发现其他地方存在指向这些路径的链接时，依然会强行收录，展示为「无可用信息」的死链；
#   更严重的是，一旦设置 Disallow 阻断抓取，爬虫永远无法抓取该文件，也就永远无法读到
#   服务器返回的 `X-Robots-Tag: noindex` 指令，从而彻底破坏了你期望的索引移除。
# 因此，开物坚持「抓取放行 + 响应头 noindex」的单一控制机制。
#
# ------------------------------------------------------------------------
# 核心论证三：为什么 Bytespider / Google-Extended / CCBot 刻意显式放行？
# ------------------------------------------------------------------------
# 1. Bytespider（字节跳动 / 豆包助手 / 搜索）：
#    开物设备语区真实数据显示，中文语区（zh-Hans-CN, zh-CN, zh-Hans 等）用户（约 1,766）
#    显著高于 en-US 语区（约 1,134）。字节跳动旗下 AI 助手是国内开发者群体最广泛的真实检索入口，
#    显式放行 Bytespider 是为了保障最大的真实用户群能检索到开物。
# 2. Google-Extended：
#    仅控制 Gemini 与 Google 搜索的 AI Overviews 摘要生成，对经典 Google Search
#    排名完全无负面影响。放行它可确保开物出现在 “claude code app” 等 AI 概览答案中。
# 3. CCBot（Common Crawl）：
#    支撑海量开源开发工具检索、学术研究及大模型生态数据源，作为 MIT 纯正开源项目理应放行。
# ------------------------------------------------------------------------
