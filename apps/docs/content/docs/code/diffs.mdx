在确认采纳工作成果前，自然要先查看改动。Kaiwu 的变更文件列表与 Review 界面支持将当前会话的全部改动汇集为连续的 Diff 进行统一浏览，无需逐个打开文件，还能将改动范围精确缩小到本次会话所做的工作。

<Callout type="info">
  查看 Diff 是常规会话界面的一部分。而暂存、提交等写入操作则相互独立且设有门禁；详见 [Git](/code/git)。
</Callout>

## 变更文件列表

变更文件列表是快速掌握和操作当前代码仓状态的高效控制界面。

你可以通过它：

- 查看文件状态（`A`、`M`、`D` 等）
- 查看每个文件的增删行数
- 暂存或取消暂存文件
- 打开单个文件的 Diff
- 在支持时执行还原/放弃更改等文件操作

该列表专为快速扫视与查阅而优化：

- 分支摘要固定在顶部
- 在变更文件列表头部可直接进入“Review”
- 提交控件统一归整在底部
- 文件路径与文件名对齐整合为一行清晰易读的标签，文件名醒目地置于改动行数摘要旁

### 变更文件范围

当存在多个可选的变更文件范围时，列表头部会变为紧凑的下拉菜单。下拉菜单中显示当前生效的范围名称及文件数，旁边保留 **Review** 按钮。

可选范围包括：

- **Changed files** / **Repository changed files**：来自最新 SCM 快照的全部代码仓当前改动。
- **Latest turn changes**：由提供商或运行时上报、归属于最近一次已完成轮次的改动。
- **Session-attributed changes**：系统尽最大努力归结出的、跨多个轮次属于本会话的改动。
- **Selected for commit**：当前被全部或部分选中以备下次提交的文件。仅在至少勾选了一个文件后才会出现。

范围选择器仅在有实际作用时出现。若当前只有代码仓视图，Kaiwu 会直接显示普通的变更文件标题，省去多余的下拉菜单。

切换范围只会改变当前浏览的列表，不会重写代码仓状态。勾选待提交的文件并不会将其变为“会话改动”，而只是让 **Selected for commit** 范围变得可用。

**全选（All）**操作能够感知当前范围：

- 在代码仓视图下，会选中所有代码仓变更文件；
- 在 Latest turn changes 下，仅选中属于该轮次范围的文件；
- 在 Session-attributed changes 下，仅选中属于该会话范围的文件；
- 在 Selected for commit 下，全选范围仅限于已选中的文件集合。

代码仓视图始终是唯一的真实依据（source of truth）。轮次与会话范围属于便捷过滤视图，其准确度取决于提供商与运行时的归因质量。

## Review

**Review** 界面专用于“一路顺畅滚动通读”当前所有未提交的实际改动。

你无需逐个打开文件，通过 Review 即可将整组 Diff 作为连续的工作视图进行集中审查。

### Review 的适用场景

在以下情况下推荐使用 Review：

- 一气呵成地滚动通读大量变更文件
- 折叠已查阅完毕的文件
- 在不丢失当前阅读进度的前提下，直接打开指定文件进入编辑模式
- 随时返回 Review 标签页，从上次中断的地方继续浏览

### Review 运行机制

- Diff 按需渐进式加载，而非一次性全部挂载。
- 系统会自动预取临近的 Diff，保证滚动时的连贯流畅。
- 若你手动折叠了某个 Diff，Kaiwu 会记住这一状态；不会因为你滚出视野又滚回来就将其自动重新展开。
- 切出 Review 界面后再切回，系统会自动恢复你先前停留的位置。

### 在 Review 中直接编辑

Review 绝非一条单向的只读死胡同。

在 Review 中，你可以将变更文件打开到专属详情标签页中进行编辑，编辑完成后即可返回 Review，原本的审查上下文完好如初。

在移动端驾驶舱布局中，Review 会在 **Tabs** 界面中打开。点击返回按钮可回到之前打开它的 Git 列表；若使用底部标签切换界面，则不会向返回栈添加多余的切页记录。

改动归因会优先使用直接操作信号与提供商/运行时的变更集。当同一个代码仓内有多个活跃会话时，归因的可靠性会有所下降，此时 Kaiwu 会优先保证代码仓的真实状态，而不是依赖脆弱的推断。
如果系统无法以高置信度支持某个范围视图，Kaiwu 会自动回退到代码仓视图或直接隐藏该范围，宁缺毋滥，避免呈现空列表或误导信息。
