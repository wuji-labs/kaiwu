会话模式与权限属于两套独立的控制维度。

在 Kaiwu 中：

- **权限**决定如何处理审批
- **会话模式**决定提供商在当前会话中的行为方式

厘清二者的区别至关重要，因为即使会话处于 **Mode = Plan**（计划模式），系统仍可能向你弹出权限确认提示词。

## 什么是会话模式

会话模式是提供商为当前会话所定义的运行模式。

例如：

- `build`
- `plan`
- 提供商专属的默认值或覆盖项

仅当当前启用的提供商或后端在本次会话中支持会话模式时，Kaiwu 才会显示 **Mode**（模式）控制项。

如果提供商未暴露任何模式，该控制项将自动隐藏。

## 模式与权限的区别

这两项设置解决的是不同的问题：

- **模式**改变的是提供商本轮尝试执行的任务类型
- **权限模式**改变的是 Kaiwu 和提供商处理审批的方式

因此，以下组合均属有效配置：

- **Mode = Plan** + **Permission = Default**
- **Mode = Plan** + **Permission = Read Only**
- **Mode = Build** + **Permission = YOLO**

模式**不会**取代权限。

## Plan（计划）模式

在当前的 Kaiwu 版本中，Plan 模式是最核心的会话模式示例。

当会话启动或切换至 **Plan** 时：

- 提供商应深入分析任务并提出行动计划
- Kaiwu 会使会话始终保持在计划模式，直至提供商主动请求退出
- 若提供商或运行时发起请求，依然可能弹出权限确认提示词

对于 Plan 模式，应当理解为：

> “让本次会话在规划模式下工作”

而不应理解为：

> “自动批准所有工具”

## 以计划模式启动会话

通过 CLI 启动：

```bash
happier claude --agent-mode plan
happier opencode --agent-mode plan
happier kilo --agent-mode plan
```

通过 App 启动：

1. 启动一个新会话
2. 打开输入控制区
3. 选择 **Mode**
4. 在可用时勾选 **Plan**

## 退出计划模式

当提供商准备结束规划并开始执行时，Kaiwu 会弹出 **Exit Plan Mode**（退出计划模式）的用户操作请求。

此处特意设计为**用户操作请求**，而非普通的权限确认提示词。

常见的选项包括：

- **Approve Plan**（批准计划）
- **Request changes**（请求修改）
- 提供商专属的各类审批分支选项

## Claude 计划模式

Claude 的计划流程是目前最具代表性的提供商专属实现。

在 Kaiwu 中：

- Claude 的 **Plan** 会显示在 **Mode** 下方
- 处于计划模式的 Claude 依然可以请求权限
- 计划审查阶段会作为 **Exit Plan Mode** 呈现

Claude 可提供以下审批选项：

- **Approve Plan**：退出计划模式，按常规流程继续执行
- **Request changes**：留在计划模式，继续修改计划
- **Approve Plan (Accept Edits)**：退出计划模式，以放宽编辑权限的策略继续执行
- **Approve Plan (Bypass All Permissions)**：退出计划模式，以类似 YOLO 的免审批权限策略继续执行

这些选项将决定 Claude 退出计划模式**之后**的运行策略。

## 批准之后会发生什么

当你批准一份计划后：

- Kaiwu 会清除该会话的计划模式覆盖项
- 会话恢复至提供商的常规工作模式
- 选定的计划后权限策略将成为生效的权限模式

例如：

- **Mode = Plan**
- **Approve Plan (Bypass All Permissions)**
- 会话恢复为构建/默认模式
- 权限模式变更为对应提供商的 YOLO 等效策略

如果你选择 **Request changes**，Kaiwu 会让会话继续保持在计划模式，并将修改意见回传给提供商。

## 通知与收件箱机制

计划审查在整个 UI 中的表现保持高度一致：

- 可显示在会话记录中
- 可显示在收件箱中
- 可触发**用户操作请求**通知

Kaiwu 将计划审查与常规权限请求明确区分开来，以便你清晰掌握当前所需决策的本质。
