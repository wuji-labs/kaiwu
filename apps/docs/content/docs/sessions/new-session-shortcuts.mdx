---
title: 新建会话快捷方式
description: 从项目或已有会话新建会话，同时复用对应的启动设置。
---
新建会话快捷方式可帮你启动相关会话，无需逐项重新检查启动配置。

当你已在某个项目中工作，或正在查看某个会话，并希望使用相同配置启动另一个智能体会话时，这项功能会非常实用。

## 快捷方式的入口

你可以通过以下位置启动预填配置的新会话：

- 会话列表中的项目分组，点击项目的 **+** 按钮
- **Session info**（会话信息）界面，点击 **New session with same setup**（使用相同配置新建会话）

这两个快捷方式都会打开常规的新建会话界面。在发送第一条提示词前，你依然可以检查或修改任何配置。

## 项目快捷方式

项目的 **+** 按钮专为常见场景设计：

1. 你正在某个项目中工作
2. 你想在该项目中启动第二个会话
3. 你希望它沿用该项目最近使用的配置

开启该功能后，Kaiwu 会读取该项目分组中最新的会话，并将其启动配置填入新建会话界面。

这意味着该快捷方式可以复用该项目最新会话的配置，而不会退回使用你在其他项目中最后选取的全局设置。

## 使用相同配置新建会话

**New session with same setup** 操作位于会话的 **Session info** 界面中。

当你希望新建的会话完全复刻某个特定会话时，可以使用该功能，例如：

- 你遇到了旁路问题，想让另一个智能体前去排查
- 你想用相同的后端、模型和权限策略再试一次
- 你想保留相同的项目、配置文件以及提供商专属选项，而不想手动逐个确认设置项

与项目的 **+** 操作不同，此操作以你当前查看的会话为基准，而不是项目分组中最新的会话。

## 会复用哪些内容

快捷方式会从源会话中复用可用的启动配置项。

其中可包括：

- 设备
- 文件夹
- 引擎或后端
- 配置文件
- 会话记录存储选项
- 权限模式
- 所选模型
- 提供商会话模式（如 Plan 模式）
- 提供商配置项覆盖（如 reasoning effort 思考程度）
- MCP 选择
- 已连接服务的选择
- 终端相关的启动选项
- 提供商专属后端模式（若提供商支持）

快捷方式本身不会自动发送提示词，它只负责预填并准备好新建会话界面。

## 不会复用哪些内容

快捷方式经过专门设计，不会继续源会话的对话内容。

它们不会复用：

- 源会话记录
- 源会话 ID
- 源会话的恢复目标
- 源会话的待处理消息
- 源会话当前的运行状态

如果你想继续某个处于闲置状态的会话，请使用恢复功能。如果你想派生对话历史，请使用会话复刻或重放。

## 现存草稿的处理方式

如果你已经写好了新建会话草稿，上下文快捷方式并不会盲目覆盖全部内容。

Kaiwu 会保留已输入的提示词和自动化草稿等内容，仅将启动配置项替换为快捷方式对应源会话的配置。

举例来说，如果你的草稿内容为：

> "Investigate the failing checkout flow"

而你在 `/repo/app` 的 Codex 会话中点击了 **New session with same setup**，输入框中的提示词仍会保留，但新建会话界面会切换为该会话对应的设备、文件夹、引擎、模型、权限以及相关会话选项。

与源会话冲突的选项会被重置或替换，包括先前草稿中失效的恢复目标和工作树检出选择。

这种机制既保留了你已写好的意图，又以快捷方式的设置为准，决定新会话在何处以何种方式启动。

## 设置项：记住项目上次会话的选择

项目的 **+** 快捷方式由 **Remember last project session selections**（记住项目上次会话的选择）控制。

前往以下路径找到该设置：

1. **Settings**（设置）
2. **Session**（会话）
3. **New session modal**（新建会话弹窗）

该设置默认处于开启状态。

开启时：

- 项目 **+** 会使用该项目分组中最新的会话作为源配置
- 保留输入框中现有的草稿内容
- 启动配置项取自该项目会话

关闭时：

- 项目 **+** 仅预选该项目的设备和文件夹
- 沿用常规的新建会话默认配置和草稿逻辑

**Session info** 中的操作始终是显式指定的：只要你选择 **New session with same setup**，新建会话界面就会采用该会话的配置。

## 与全局记忆设置的区别

Kaiwu 依然保留了常规的新建会话默认配置与草稿功能。

快捷方式的行为则针对性更强：

- 常规的 **New Session** 使用当前的草稿或默认配置
- 项目 **+** 可以使用该项目中最新的会话配置
- **New session with same setup** 则精确采用你当前正在查看的会话配置

这避免了一个常见问题：在其他项目中使用的设置，意外影响了你当前正在处理的项目的新建会话。

## 常见使用场景

### 排查旁路问题

你在处理某个功能的会话中发现了另一个不相干的缺陷。

打开当前会话的 **Session info**，选择 **New session with same setup**，然后针对该旁路问题输入专门的提示词。

### 在同一项目中运行第二个智能体

在会话列表中点击项目的 **+** 按钮。

Kaiwu 会让你保持在同一项目上下文中；若已开启该设置，还会自动复用该项目最新会话的引擎、模型、权限、配置文件和各项选项。

### 隔离不同项目的专属后端选择

某个项目可能使用的是配置好的 ACP 后端，而另一个项目则使用内置提供商。

开启 **Remember last project session selections** 后，项目快捷方式会使用该项目自身的最新配置，而不会从其他地方带入全局最后使用的后端。

### 保留提示词并切换到正确的配置

如果你已经在新建会话界面中输入了提示词，随后发现需要改用某个现有会话的相同配置启动，直接使用上下文快捷方式即可。

提示词会完好保留，启动配置项则会替换为该会话的配置。
