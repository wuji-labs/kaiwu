---
title: 继续会话
description: 接手已有的对话——无论是你智能体自身的会话，还是已沉寂的 Kaiwu 会话——并在之后决定其归属。
---
并非所有会话都始于 Kaiwu。也许你昨天在终端里开了个头，又或者某个 Kaiwu 会话隔夜挂起进入了非活跃状态，而你现在想继续处理。Kaiwu 可以接入所有这些会话——但以*何种方式*接入，会决定你后续能进行的操作。这是在开始之前最值得厘清的一个核心差异。

## 会话记录归谁所有

Kaiwu 中的每个会话都属于以下两类之一，分别对应会话列表中的 **Kaiwu** 和 **Direct** 标签页：

| | Kaiwu 会话 | Direct 会话 |
| --- | --- | --- |
| 权威数据源 | Kaiwu | 设备上的 Agent |
| 跨设备可见 | 是 | 仅当该设备可达时可见 |
| 设备离线时 | 依然可读 | 不可用，直至设备重新上线 |
| 会话记录存储位置 | 存储在 Kaiwu 中（加密） | 保留在 Agent 本地 |

两者都会持久保存历史记录——“Direct”并不代表未保存，而是指 Agent 自身的日志才是权威记录，Kaiwu 只是读取这些日志，并不拥有它们的所有权。

新会话默认创建为哪种类型完全由你决定：
**设置 → 会话 → 默认会话类型**。

<Callout type="info">
  Direct 会话目前为实验性功能。此外，在将其导入之前，必须保证其所属设备始终保持可达状态——这也是你最先感受到的实际差异。
</Callout>

## 查找 Agent 已有的会话

Kaiwu 能够列出已连接设备上已存在的对话，免去了记忆标识符的麻烦。

在新会话创建流程中，选择 AI 后端与设备，展开输入控件并找到 **恢复会话**。在支持列出会话的 Agent 旁会出现 **浏览会话** 按钮，从列表中选择一个会话即可自动填入对应字段。

该列表的作用域限定为你此前选定的 Agent 与设备。对于 Codex，其范围还会进一步收缩到当前认证方式所对应的 Codex 主目录；因此，已连接的服务账号与本地的 `~/.codex` 会显示不同的历史记录。

若该 Agent 不支持列出会话，你也可以直接粘贴该 Agent 自身的会话标识符。对于已有的会话，可以在“会话信息”中查看该标识符。

## 接管 Direct 会话

直接打开某个——或者更确切地说，你自己的——Agent 会话，你可以阅读并实时跟踪其进展。当你想要在 Kaiwu 中*主导*该会话时，就需要执行接管操作，此时 Kaiwu 会询问你的接管方式：

- **接管**——在 Kaiwu 中控制该会话，但不导入会话记录。它仍保持为 Direct 会话，且以 Agent 本地的日志为权威记录。
- **接管并导入**——将会话记录导入 Kaiwu，并作为常规 Kaiwu 会话继续运行，在多台设备间保持同步。

还有第三个选项，不过它只会在特定情况下出现：当 Kaiwu 检测到仍有受信任的本地进程挂接在该会话上时，会提供 **先尝试停止本地进程** 选项，并在确认后执行 **停止并接管**。若某个终端仍在占用该对话，直接接管会导致两者冲突，此时便应选择此项。

在前两者之间做选择，本质上取决于你希望后续的历史记录保存在哪里。如果你明天想在手机上继续处理该会话，就选择导入；如果你更看重 Agent 自身的日志记录，就保持 Direct 状态。

## 有哪些可用控制项

如果 Kaiwu 只是在跟踪某个 Direct 会话，而非进行本地控制，界面会显示会话记录与历史（包括由提供商支持的后台任务），但无法启动子 Agent、进行引导或停止。对于无法生效的控制项，Kaiwu 会直接隐藏，而不是提供一个注定会失败的操作。

一旦会话进入本地控制状态，所有操作能力都会恢复：启动子 Agent、引导与发送、停止以及取消。

非活跃的 **Kaiwu** 会话则是另一种情况。如果该会话支持恢复且其所属设备处于可达状态，Kaiwu 可以先恢复会话，然后再为你开放这些控制项。在开发版构建中，即便设备离线，其输入框也依然可用：Kaiwu 会将你发送的内容排入队列，并在其所属守护进程恢复后自动恢复会话。

## 设备离线时

对于 **Direct** 会话，会话记录将无法刷新，实时跟踪也会暂停，且必须等待设备重新连接后才能执行接管。

对于 **Kaiwu** 会话，由于会话记录已保存在 Kaiwu 中，因此它不仅常驻在会话列表中，还始终保持可读。在开发版构建中，可恢复的会话依然支持编辑输入。会话状态仍会显示为离线，且输入框上方的横幅会提示当前排队的消息已暂存，直至设备重新上线。你可以选择让消息继续排队，也可以在“会话设置”中针对后续发送关闭自动恢复功能。

## 各 Agent 的支持情况

- **Codex**——浏览范围涵盖常规 Codex 主目录以及受支持的已连接服务目录，Kaiwu 可以直接跟踪 Codex 的会话记录。详见 [Codex](/agents/codex)。
- **Claude**——Kaiwu 可以从托管 Claude 会话的设备上浏览并打开这些会话。会话标题与会话记录的连贯性取决于会话日志暴露的内容。详见 [Claude](/agents/claude)。
- **OpenCode**——支持直接浏览由服务器托管的会话；当 OpenCode 服务端本身就是权威数据源时，这种方式十分顺理成章。详见 [OpenCode](/agents/opencode)。

有关各 Agent 本身是否支持恢复其会话，请参阅 [Agent 能力](/agents/capabilities)。
