## 入门指南：必填项与推荐项

服务端支持多种存储、身份验证与网络拓扑，因此环境变量较多。绝大多数部署只需配置其中一小部分。

**多数生产环境部署的必填项**

- `HANDY_MASTER_SECRET`
  `apps/server` 的必填项，用于保护服务端管理的密钥。请使用长随机字符串，并在多次重启之间保持稳定不变。
- `DATABASE_URL`（完整版 / 外部数据库）
  `KAIWU_DB_PROVIDER=postgres|mysql` 时必填。
- `KAIWU_DB_PROVIDER`
  选择数据库后端（`.env.example` 中默认为 `postgres`）。
- 所选后端的文件存储配置：
  - `KAIWU_FILES_BACKEND=local`：无需额外环境变量，或
  - `KAIWU_FILES_BACKEND=s3`：需要 `S3_*` 凭据 + `S3_PUBLIC_URL`

**强烈推荐（避免配对及移动端 URL 混淆）**

- `KAIWU_PUBLIC_SERVER_URL`
  服务端的规范/共享 URL，用于嵌入二维码与深层链接，并通过 `GET /v1/features` 对外公布。该地址应为手机能够直接访问的 URL（推荐使用 `https://...`）。
- `KAIWU_WEBAPP_URL`（自托管 Web UI 或用于 OAuth 重定向回跳）
  Web 客户端和 OAuth 重定向的基础 URL。如果使用托管在 `https://kaiwu.chengqiyun.com` 的 Web 应用，则为可选项。

**置于反向代理后时的推荐配置**

- `KAIWU_SERVER_TRUST_PROXY=1`：适用于常见的单代理架构（Caddy/Nginx/Traefik），以便服务端能安全地利用 `X-Forwarded-*` 进行 `request.ip` 与协议检测。

**可选优化项**

- API 速率限制：`KAIWU_API_RATE_LIMITS_*`（下文附有推荐基准配置）
- 指标监控：`METRICS_*`

## 规范模板

请使用 `/apps/server/.env.example` 作为规范模板。

典型工作流程：

```bash
cp apps/server/.env.example apps/server/.env
```

随后：

- 本地/开发环境：从 `apps/server/.env` 加载配置值，
- Docker/Compose/各部署平台：将同一套键值对复制到环境或密钥管理器中。

## 网络与反向代理

- `KAIWU_SERVER_TRUST_PROXY`（可选）
  控制服务端运行在反向代理之后时，是否信任 `X-Forwarded-*` 请求头以获取客户端 IP 和协议。
  - 未设置：使用框架默认行为（不信任转发头）
  - `true`：信任所有代理跳（仅在服务端无法被外部直接访问时才安全）
  - `false`：永不信任转发头
  - `⟦K5⟧`：信任最后 N 跳（`0` 等同于 `false`；典型单代理架构推荐设置为 `1`）

### WebSocket（实时通信及“设备在线”必需）

Kaiwu 的实时同步（以及设备在线状态检测）通过 Socket.IO 实现，路径为：

- `GET /v1/updates`（轮询 + WebSocket 升级）

若反向代理（或 CDN）未能正确转发 `/v1/updates` 的 **WebSocket 升级请求**，客户端可能表面上连接成功，但设备会一直显示离线。

常见症状：

- 界面/手机端显示**无在线设备**或“需要操作”
- 服务端诊断信息包含 `machine.none_online`
- 守护进程日志显示“正在连接至……”，但 `/v1/machines` 报告 `active: false`

#### Nginx（配置示例）

如果在 Nginx 上终止 TLS，请确保其正确转发 WebSocket 升级请求（针对所有路径，或至少针对 `/v1/updates`）：

```nginx
location /v1/updates/ {
  # Use the server's HTTP port (usually 3005; some managed/self-host flows use 53288).
  proxy_pass http://127.0.0.1:<port>;
  proxy_http_version 1.1;

  proxy_set_header Upgrade $http_upgrade;
  proxy_set_header Connection "upgrade";

  proxy_set_header Host $host;
  proxy_set_header X-Forwarded-Proto $scheme;
  proxy_set_header X-Forwarded-Host $host;
  proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
}
```

#### 快速检查（WebSocket 升级是否正常？）

在任何能够访问公共 HTTPS URL 的设备上运行：

```bash
KEY="$(openssl rand -base64 16)"
curl -i -sS \
  -H "Connection: Upgrade" \
  -H "Upgrade: websocket" \
  -H "Sec-WebSocket-Version: 13" \
  -H "Sec-WebSocket-Key: $KEY" \
  "https://api.example.com/v1/updates/?EIO=4&transport=websocket" | head -n 5
```

预期输出：`HTTP/1.1 101 Switching Protocols`。

#### 临时融通方案（守护进程端）

如果无法立即调整反向代理，可以先强制守护进程通过轮询方式连接：

```bash
KAIWU_SOCKET_TRANSPORTS=polling,websocket kaiwu daemon restart --takeover
```

## 规范 URL（二维码/深层链接，推荐配置）

- `KAIWU_PUBLIC_SERVER_URL`
  服务端的规范/共享 URL。客户端会将此地址嵌入终端连接的深层链接和二维码中，服务端也会通过 `GET /v1/features` 在 `capabilities.server.canonicalServerUrl` 下对外公布。
  - 请使用手机可正常访问的 URL（推荐 `https://...`）。
  - 若有意仅在局域网内运行，使用 `http://⟦K6⟧:3005` 即可，但二维码与深层链接将仅在同一局域网或 VPN 内有效。
  - 若未设置该项，或当前活动的服务端 URL 解析为仅回环地址（`localhost`、`127.0.0.1`、`::1`、`*.localhost`），Kaiwu 可能会在面向移动端的二维码/深层链接中特意省略服务端 URL，以避免嵌入无法访问的失效地址。
- `KAIWU_WEBAPP_URL`（别名：`HAPPY_WEBAPP_URL`）
  Web 客户端的基础 URL。服务端会通过 `GET /v1/features` 在 `capabilities.server.webappUrl` 下对外公布。
  - 使用托管版 Web 应用：保持默认值 `https://kaiwu.chengqiyun.com`。
  - 自托管 UI：请设置为 UI 的源地址（通常与 `KAIWU_PUBLIC_SERVER_URL` 相同）。

对用户体验的影响：

- **添加手机**
- **恢复账号**
- **CLI/移动端身份验证二维码链接**
- **配置服务端链接**

当嵌入的服务端 URL 可被目标手机/设备直接访问时，上述功能体验最佳。

如果用户看到提示要求在手机上手动配置服务端，通常意味着当前服务端 URL 为仅回环地址，无法安全地跨设备共享。

## Tailscale Serve 自动推断（可选）

如果未设置 `KAIWU_PUBLIC_SERVER_URL` 且服务端通过 `tailscale serve` 暴露，服务端可以在启动时尽力推断 `https://⟦K7⟧.⟦K8⟧.ts.net` URL。

- `KAIWU_TAILSCALE_INFER_PUBLIC_URL`（默认值 `true`）
  设置为 `0` 可禁用自动推断。
- `KAIWU_TAILSCALE_BIN`（默认值 `tailscale`）
  覆盖 tailscale 二进制文件的路径或名称。
- `KAIWU_TAILSCALE_SERVE_STATUS_TIMEOUT_MS`（默认值 `750`）
  `tailscale serve status` 探测的超时时间（上限为 `1..10000`）。

## API 速率限制

速率限制基于 `@fastify/rate-limit`。所有 `*_WINDOW` 值均支持人类可读的时间长度，如 `30 seconds`、`1 minute`、`5 minutes`。

全部 33 个端点的具体限制（包括默认值、计入维度以及对应的两组环境变量）均根据服务端的速率限制目录自动生成，详见 [API rate limits](/self-hosting/rate-limits)。这些变量名在运行时由端点 ID 推导而来，并未以字面量形式出现在源码中，手动配置部署时极易遗漏。

全局控制项：

- `KAIWU_API_RATE_LIMITS_ENABLED`（默认值 `true`）
  设置为 `0` 或 `false` 可禁用全部 API 速率限制。
- `KAIWU_API_RATE_LIMITS_GLOBAL_MAX`（默认值 `0`）
  作用于所有路由的可选全局限制。设置为 `0` 可将其禁用。
- `KAIWU_API_RATE_LIMITS_GLOBAL_WINDOW`（默认值 `1 minute`）

### 内置密钥质询登录路由

Kaiwu 默认的“设备密钥”注册与登录流程使用 `POST /v1/auth`。

服务端运维人员可以禁用此内置登录路由（例如当所有访问均需经由 GitHub 或 OIDC 等提供商时）。

- `KAIWU_FEATURE_AUTH_LOGIN__KEY_CHALLENGE_ENABLED`（默认值 `1`）

注意：若禁用密钥质询路由，请确保已配置至少一个可用的提供商（否则服务端会在启动时快速失败以防止锁定）。

### 无密钥 OAuth 登录（可选）

Kaiwu 支持将 OAuth 提供商（GitHub/OIDC）作为**无密钥登录方式**，账号无需设备密钥即可存在（专为企业版与明文存储部署设计）。

无密钥 OAuth 受以下特性环境变量控制：

- `KAIWU_FEATURE_E2EE__KEYLESS_ACCOUNTS_ENABLED`（默认值 `0`）
- `KAIWU_FEATURE_AUTH_OAUTH__KEYLESS_ENABLED`（默认值 `0`）
- `KAIWU_FEATURE_AUTH_OAUTH__KEYLESS_PROVIDERS`（逗号分隔的提供商 ID 允许列表，例如 `github,okta`）
- `KAIWU_FEATURE_AUTH_OAUTH__KEYLESS_AUTO_PROVISION`（默认值 `0`）

说明：

- `KAIWU_FEATURE_AUTH_OAUTH__KEYLESS_AUTO_PROVISION=1` 控制是否允许在首次登录时创建新的无密钥账号。
- 无密钥自动置备要求同时启用无密钥账号与明文默认配置（当前先决条件详见 [Server Auth](/self-hosting/auth)）。

## 特性门控

以下每项决定了服务端是否对外公布对应的能力。它们默认开启：客户端仍需启用相应的开关，且其中数项在客户端属于实验性功能，因此通常保持默认即可。若希望在部署中彻底禁用某项能力（无论客户端如何请求），可将其设置为 `0`。

包含无对应环境变量项在内的完整门控能力清单，详见 [Feature flags](/extras/feature-flags)。

- `KAIWU_FEATURE_ATTACHMENTS_UPLOADS__ENABLED`（默认值 `1`）
- `KAIWU_FEATURE_AUTOMATIONS__ENABLED`（默认值 `1`）
- `KAIWU_FEATURE_AUTH_PAIRING__DESKTOP_QR_MOBILE_SCAN_ENABLED`（默认值 `1`）
- `KAIWU_FEATURE_CHANNEL_BRIDGES__ENABLED`（默认值 `1`）
- `KAIWU_FEATURE_CHANNEL_BRIDGES_TELEGRAM__ENABLED`（默认值 `1`）
- `KAIWU_FEATURE_CONNECTED_SERVICES_ACCOUNT_GROUPS__ENABLED`（默认值 `1`）——账号池

- `KAIWU_FEATURE_SESSIONS_DRAFTS__ENABLED`（默认值 `1`）——同步已有与新建会话草稿
- `KAIWU_FEATURE_SESSIONS_FOLDERS__ENABLED`（默认值 `1`）
- `KAIWU_FEATURE_SESSIONS_HANDOFF__ENABLED`（默认值 `1`）
