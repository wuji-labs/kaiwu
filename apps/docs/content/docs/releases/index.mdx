Kaiwu 提供三个通道，所选通道不同，获得的内容也不同。这种差异至关重要：某项修复可能已在 `dev` 上线数周，之后才会合并至 `stable`。

| 通道 | 命令 | 说明 |
| --- | --- | --- |
| **stable** | `happier` | 生产正式版。稳健保守，适合绝大多数用户。 |
| **preview** | `hprev` | 候选发布版（RC）—— 即将成为 stable 的版本。 |
| **dev** | `hdev` | 集成通道。所有改动均最先合并至此，可能不够稳定。 |

不同通道支持并行安装，并各自维护独立的 shim 命令入口。若某个项目需要最新的修复，你可以运行 `hdev`，同时让 `happier` 继续保持在 stable 版本。各通道均独立根据自身通道更新。

各通道的安装命令详见 [CLI](/apps/cli) 页面。

## 代码改动如何发布

开发采用三分支模型，代码呈单向流动：

```
dev  →  preview  →  main
```

`dev` 是集成分支，也是代码仓库的默认分支 —— 所有改动都会优先合入这里。`preview` 是发布候选分支，preview 构建即出自该分支。`main` 则对应 stable。版本号与变更日志的生成发生于代码晋升*之前*的 `dev` 源码区间，因此 `main` 是流向的目标分支，而非日常开发的起点。

<Callout type="info">
  如果你正在使用 `stable` 并遇到了疑似已知 Bug 的问题，不妨先确认该问题是否已在 `dev` 中修复。这两个版本之间的差距可能相当大。
</Callout>

## 切换通道

安装其他通道并不会移除当前已有的通道 —— 只需运行目标通道的安装端点，并使用对应的命令即可。`happier status` 会显示当前所调用 CLI 所属的通道，这是确认当前实际运行版本最快捷的方式。
