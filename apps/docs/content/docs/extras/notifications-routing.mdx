Kaiwu 的通知具备会话感知与多服务器感知能力。

与通知交互时，Kaiwu 会尽量带你直达需要处理的具体位置：

- 目标**会话**
- 正确的**服务器配置**
- 对**权限操作**采取最安全的操作机制

这样可以避免进入错误的服务器，或在非预期的服务器上静默批准请求。

## 常见通知类型

- 轮次完成 / “已就绪”
- 权限操作
- 动作请求
- 共享/协作事件

## 点击通知会发生什么

若通知包含会话路由，Kaiwu 会打开对应会话。

若通知所属的已保存服务器与当前活跃的服务器不同：

- Kaiwu 会先切换到该已保存服务器
- 随后打开对应会话

普通通知点击以及动作请求通知中的 `Answer` 操作，均默认采用该行为。

## 点击通知操作按钮会发生什么

在移动端 App 上，当前可交互的通知操作包括：

- **权限请求**：`Allow`、`Deny`
- **用户动作请求**：`Answer`

两者的行为设计特意有所区分：

- `Allow` 与 `Deny` 会打开 App，在确保安全的前提下发送权限响应，随后打开对应会话
- `Answer` 会直接打开 App 并定位到对应会话，方便你结合上下文作答

用户动作请求包含如下场景：

- **AskUserQuestion**
- **Exit Plan Mode**

目前，Kaiwu **不会**尝试直接在通知栏中发送自由文本或多选回答。操作按钮的作用是提供一条快速通道，带你返回正确的会话。

## 服务器感知安全规则

### 1) 服务器已处于活跃状态

若通知目标是当前已处于活跃状态的服务器：

- Kaiwu 会立即执行对应操作（例如 `Allow` / `Deny`）
- 随后打开对应会话

### 2) 服务器已保存，但未处于活跃状态

若通知目标是某个已保存但当前未处于活跃状态的服务器配置：

- Kaiwu 会切换到该已保存服务器
- 执行相应操作（若适用）
- 打开对应会话

### 3) 服务器未保存，且设备上尚未保存任何服务器

若这实际上是设备上的首个服务器：

- Kaiwu 可能会自动添加并切换到该服务器，确保通知深度链接依然可用
- Kaiwu 打开对应会话
- 出于安全考虑，Kaiwu 依然**不会**在未保存的服务器上自动发送 `Allow` / `Deny`

这主要是为初次运行或自托管场景提供的引导便利。

### 4) 服务器未保存，且设备上已有保存的服务器

若 App 中已存在其他服务器记录，Kaiwu **不会**自动添加新传入的服务器。

而是会：

- 暂存待跳转的目标地址
- 打开**服务器设置**
- 预填传入的服务器 URL
- 显示该服务器尚未保存的提示

当你选择**添加并使用**后，Kaiwu 会自动继续前往原本的目标会话。

## 流程保持严格的原因

通知操作虽然便捷，但权限响应关乎系统安全。

因此，Kaiwu 仅在能确认目标服务器满足以下条件时，才会自动发送权限响应：

- 当前已处于活跃状态，或
- 本地已保存该服务器，且能够显式切换过去

若遇到未知服务器，Kaiwu 会退化为仅跳转页面并交由人工核对，而不是静默执行批准操作。

## 前置条件

- App 已向所选服务器注册推送 Token。
- CLI/守护进程与 App 使用相同的服务器配置。
- 在多服务器架构下，各服务器配置均已正确配置。

## 故障排查

若点击通知打开了错误的上下文：

1. 在 App 中核对当前活跃的服务器配置。
2. 在 CLI 中针对正确的服务器配置重新运行 `happier auth login`。
3. 确认该服务器配置的推送 Token 注册状态。
4. 若通知来自尚未保存的服务器，请先在已预填的**服务器设置**页面中将其添加。
