Kaiwu 的各项功能并非对所有人默认全量开启。一项能力可能受到三道关卡的管控；只有这三处判定全部通过，该功能才真正可用：

1. **服务端**声明其支持的功能。自托管用户可通过 `HAPPIER_FEATURE_*` 环境变量进行配置；在 Kaiwu Cloud 上，这部分已由系统预先设定。
2. **构建产物**可直接通过 `HAPPIER_BUILD_FEATURES_ALLOW` 与 `HAPPIER_BUILD_FEATURES_DENY` 禁用特定功能，不受服务端状态影响。
3. **用户自行控制**：你可以在**设置 → 功能**（**Settings → Features**）中主动开启部分功能。

功能目录中的所有功能均遵循**默认关闭（fail-closed）**原则：客户端若无法明确获知某项功能是否可用，便会直接将其视作不可用。正因如此，当服务端无法连接时，相关功能似乎会凭空消失；而自托管服务端如果配置有误，对应功能也会被直接隐藏，绝不会以半开启的异常状态呈现。

功能目录中共有 72 项功能。其中 22 项配有用户可直接操作的开关；其余 50 项则在上游层级便已确定，无法手动切换。

客户端开关仅能呈现服务端已允许的功能。如果服务端尚未声明某项能力，在本地强行开启开关也不会生效。
