## Windows 上的远程会话

从 Kaiwu App 在 Windows 设备上启动会话时，你可以选择该会话在 Windows 本地的承载方式。

主要选项包括：

- **Hidden** —— 无可见终端窗口，最适合纯 App 远程操作
- **Windows Terminal** —— 在独立的 Windows Terminal 窗口中启动会话
- **Console** —— 在常规的可见控制台窗口中启动会话

这一设计取代了早期“显示可见控制台窗口”的思路，提供了更清晰的模式化管理方案。

## 该选择哪种模式？

### Hidden

如果你主要通过 Kaiwu App 控制会话，后续不打算切回 Windows 本地终端，请选择 **Hidden**。

这种模式不会弹出可见的终端窗口，受到的干扰最小。

### Windows Terminal

如果你希望获得贴近 Windows 原生的“远程启动，稍后在本地继续”的工作流，请选择 **Windows Terminal**。

通常在以下场景中这是最佳选择：

- 你平时就使用 Windows Terminal；
- 你希望 App 启动的会话后续能在 Windows Terminal 窗口中继续运行；
- 你打算使用 `happier attach ⟦K1⟧` 重新唤起该窗口并置顶聚焦。

### Console

如果你需要可见的本地终端窗口，但不想依赖系统是否安装或识别到 Windows Terminal，请选择 **Console**。

在以下情况下，该模式是理想的备选方案：

- Windows Terminal 不可用；
- 你更偏好普通的控制台窗口；
- 你仍希望保留一个可见的本地会话，以便后续切回操作。

## 如何配置

### 全局默认设置

依次打开：

1. **Settings**
2. **Session**
3. 找到 **Windows** 区域

你可以在此处为 Windows 设备上由 App 启动的新会话选择默认的远程会话模式。

### 单设备覆盖设置

在 Windows 设备的详情页中，你可以针对该特定设备覆盖全局默认设置。

适用于以下场景：

- 笔记本电脑默认使用 **Windows Terminal**；
- 远程构建机保持 **Hidden**；
- 未安装 Windows Terminal 的设备始终使用 **Console**。

### 单会话覆盖设置

当所选设备为 Windows 时，新建会话流程中会显示一个 Windows 模式标签。你可以通过该标签针对当前新建的单次会话单独覆盖模式。

优先级顺序为：

1. 单会话选择
2. 设备覆盖设置
3. 全局会话设置

## Windows 上的 Attach 行为

若会话是在支持 Attach 的 Windows 模式下启动的：

- **Windows Terminal** 会话可通过 `happier attach ⟦K2⟧` 重新打开或聚焦
- **Console** 会话可通过 `happier attach ⟦K3⟧` 切回前台

若会话是在 **Hidden** 模式下启动的，其设计初衷是供 App 远程使用，不支持后续在本地终端中 Attach。

## 注意事项与限制

- 此设置仅适用于 **Windows** 设备。
- Windows 原生工作流通常使用 **Windows Terminal** 或 **Console** 模式，而非 tmux。
- 如果在 WSL 或其他包含 tmux 的 POSIX 环境中工作，依然可以使用基于 tmux 的 Attach 工作流。

## 环境变量（进阶）

直接通过守护进程或 CLI 操作时，你也可以通过环境变量来设置默认的 Windows 远程会话模式。

旧版取值（如 `HAPPIER_WINDOWS_REMOTE_SESSION_CONSOLE=visible`）会被直接兼容处理为现代的 **Console** 模式。

对于从 App 启动的会话，App 内的用户设置优先级依然更高。
