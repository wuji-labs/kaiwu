后端配置文件可将**具名后端配置**保存下来，并在每次启动会话时直接复用。

适合使用配置文件的场景：

- 将提供商切换到其他端点或认证方案
- 在多个会话间复用相同的环境变量
- 一次性绑定所需机密，免去重复输入的麻烦
- 让客户端 UI、守护进程和 CLI 始终使用**随账户同步的同一套配置文件定义**
- 使用同一套配置文件模型，对接内置提供商或已配置的 **Custom ACP** 后端

应用示例：

- 将 Claude 指向 **DeepSeek** 或 **Z.AI** 运行
- 让 Codex 使用 **OpenAI API 密钥**或 **Azure OpenAI** 运行
- 让 Gemini 使用 **API 密钥**或 **Vertex AI** 运行
- 创建包含专属环境变量的自定义配置文件，例如 “Work Codex” 或 “Staging Claude”

## 配置文件包含的内容

配置文件可包含以下内容：

- 会话启动时注入的**环境变量**
- 会话启动前必须就绪的变量**依赖项**
- 针对所需机密的**已保存机密绑定**
- 与一个或多个后端的**兼容性设置**，包括已配置的 ACP 后端
- **各后端的默认启动偏好设置**，例如支持的默认权限和会话记录存储设置

配置文件**仅在启动新会话时生效**。
会话一旦启动，其配置文件即**固定不变**。若要切换配置文件，请启动新会话。

## 内置配置文件与自定义配置文件

Kaiwu 预置了针对常见环境的内置配置文件，同时也支持创建自定义配置文件。

内置示例包括：

- 面向 CLI 登录环境的 **Anthropic (Default)**、**Codex (Default)** 和 **Gemini (Default)**
- 用于兼容 Claude 路由的 **DeepSeek (Reasoner)** 和 **Z.AI (GLM-4.6)**
- 面向 Codex 的 **OpenAI (GPT-5)** 和 **Azure OpenAI**
- **Gemini (API key)** 与 **Gemini (Vertex AI)**

你也可以针对自定义端点、模型和环境变量创建专属的配置文件。

注意：在 UI 中编辑内置配置文件会生成一份**自定义副本**，内置版本本身保持不变。

## 启用配置文件

配置文件功能在客户端 UI 中默认关闭，需手动开启：

1. 打开 **Settings → Features**
2. 开启 **Profiles**
3. 打开 **Settings → Profiles**

若未开启 Profiles，客户端将直接回退到设备本地环境，无法选择配置文件。

## 在客户端中创建配置文件

1. 打开 **Settings → Profiles**
2. 点击 **Add Profile**
3. 输入清晰易辨的配置名称
4. 选择该配置兼容的后端
5. 添加 Kaiwu 在会话启动时需要注入的环境变量
6. 将所需变量标记为相应类型：
   - **Secret**：由 Kaiwu 通过已保存的机密、设备环境变量或交互式提示输入流程来提供
   - **Config**：目标设备上必须预先存在的环境变量
7. 保存配置文件

推荐实践：

- 将提供商选择、Base URL 和模型 ID 直接写入配置文件
- 将 API 密钥/令牌标记为**必要机密**
- 针对跨设备复用的凭据，建议使用已保存的机密进行管理

## 在客户端 UI 中使用配置文件

启用 Profiles 后：

1. 从客户端启动新会话
2. 选择要运行的后端
3. 选择所需的配置文件
4. 若 Kaiwu 提示缺少必要配置，按提示补齐

对于从 UI 启动或远程启动的会话，Kaiwu 可通过以下途径获取所需机密：

- 守护进程所在主机上的**设备环境变量**
- 绑定到该配置文件的**已保存机密**
- 在会话启动时输入的**仅当前会话有效的临时机密**

若目标设备缺少必要的配置环境变量，客户端会阻止启动，避免运行异常会话。

会话启动后，所选配置文件会显示在 **Session Info → AI Profile** 中。

已配置的 ACP 后端与内置后端遵循相同的处理流程。如果某个配置文件专为特定后端设计，Kaiwu 会直接保持两者的对应关系。

## 在 CLI 中使用配置文件

CLI 会读取与客户端相同的账户设置，登录后即可直接使用已保存的自定义配置文件。

### 列出可用配置文件

```bash
happier profiles list
happier profile list
```

脚本调用方式：

```bash
happier profiles list --json
```

若需要强制刷新设置：

```bash
happier profiles list --refresh-settings
```

若未登录，CLI 仅会显示内置配置文件。

### 使用指定配置文件启动会话

启动会话时传入 `--profile ⟦K6⟧`：

```bash
happier --profile anthropic
happier claude --profile deepseek
happier codex --profile openai
happier codex --profile "Work Codex"
happier gemini --profile gemini-vertex
```

配置文件匹配规则：

- 优先完全匹配 **配置文件 ID**
- 若未命中，则按**不区分大小写的名称**进行匹配
- 若存在同名配置文件，Kaiwu 会提示改用 ID 指定

CLI **不会**自动沿用上次使用的配置文件，必须显式指定 `--profile`。

### CLI 的机密解析机制

当配置文件需要机密时，CLI 会按以下顺序依次解析：

1. 当前 Shell 环境变量
2. Kaiwu 设置中绑定的已保存机密
3. TTY 交互式会话中的终端提示输入

如果在非交互模式下运行 CLI 且缺少所需机密，CLI 会直接报错并给出引导提示，避免启动异常会话。

在本地通过 CLI 启动时，所需的配置环境变量必须已存在于 Shell 环境中。

## 已保存的机密与绑定

配合已保存的机密使用，能最大化发挥配置文件的优势：

- 在客户端中保存一次机密
- 将其绑定到配置文件所需的对应环境变量
- 在客户端和 CLI 中均可直接复用该绑定关系

这在以下场景中尤为实用：

- `OPENAI_API_KEY`
- `DEEPSEEK_AUTH_TOKEN`
- `GEMINI_API_KEY`
- 其他不想频繁重复输入的提供商令牌

另请参阅：

- [Connected services](/accounts/connected-services)
- [Provider integrations](/agents/provider-integrations)

## 实用示例

### 示例：通过 DeepSeek 运行 Claude

如果希望 Claude 会话通过 DeepSeek 的 Anthropic 兼容端点运行，可直接使用内置的 **DeepSeek (Reasoner)** 配置文件。

- 客户端 UI：启动 Claude 会话并选择 **DeepSeek (Reasoner)**
- CLI：`happier claude --profile deepseek`

Kaiwu 会自动应用所需的认证令牌以及 Claude 兼容的环境变量映射。

### 示例：通过 OpenAI API 密钥运行 Codex

若希望 Codex 使用 OpenAI API 密钥而非设备登录凭据，请使用 **OpenAI (GPT-5)**。

- 客户端 UI：启动 Codex 会话并选择 **OpenAI (GPT-5)**
- CLI：`happier codex --profile openai`

### 示例：自定义工作配置文件

在需要以下配置时，可创建如 **Work Codex** 这样的自定义配置文件：

- 固定端点
- 固定模型
- 可复用的令牌绑定
- 在会话历史与 Session Info 中显示清晰的标识

### 示例：为 Custom ACP 后端创建配置文件

如果配置了诸如 **Review Bot** 等自定义 ACP 后端，可以为其创建专属的兼容配置文件。

该做法适用于以下场景：

- 需要针对特定后端设置端点或环境变量
- 需要设置该后端专属的默认权限
- 需要设置该后端专属的默认会话记录存储策略
- 避免该配置文件出现在其他无关后端的选项中

## 故障排查

### “CLI 中未显示我的配置文件”

请检查：

- 是否已通过 `happier auth login` 完成登录
- 配置文件是否存在于 **Settings → Profiles** 中
- 配置文件是否保存在当前连接的同一 Kaiwu 账户或服务器下

运行以下命令检查：

```bash
happier profiles list --refresh-settings
```

### “CLI 提示缺少机密”

解决方法（任选其一）：

- 在 Shell 中导出所需的环境变量
- 在客户端中将已保存的机密绑定到该配置文件
- 在交互式终端中重新运行该命令，根据 Kaiwu 的提示手动输入

### “客户端提示配置文件未就绪”

这通常意味着所选设备上缺少以下某项依赖：

- 所需的机密
- 所需的配置环境变量
- 基于设备登录的配置文件所需的 CLI 登录状态

请在 **Settings → Profiles** 中打开该配置文件，检查具体的依赖项要求。
