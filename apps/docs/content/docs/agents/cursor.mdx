Kaiwu 通过本地的 `cursor-agent` CLI，基于 Agent Client Protocol 运行 **Cursor**。只要该 CLI 在目标设备上正常运行，`happier cursor` 即可在当地启动会话。你可以在手机、浏览器或另一台电脑上查看、引导并审批该会话。

<Callout type="warn" title="实验性">
Cursor 的集成起步晚于 Claude、Codex 或 OpenCode。虽然它能正常工作且有人日常使用，但未来变动可能会更频繁，而且 Kaiwu 在其他地方提供的部分会话功能此处暂不支持——详情请见下方的[限制](#limits)。
</Callout>

## 前提条件

Kaiwu 负责调度你的编程智能体，本身并不内置智能体。在 `happier cursor` 执行任何操作之前，必须在运行会话的设备上安装 `cursor-agent` 并完成登录。如果它在该设备的终端中无法运行，通过 Kaiwu 也同样无法使用。

## 安装 CLI

请按照 Cursor 最新的 CLI 安装指引进行安装，然后确认其能正常运行：

```bash
cursor-agent --version
```

在 Kaiwu 中无需离开应用即可完成相同检查：打开 **Settings → AI & Agents → AI backends → Cursor**，查看所选设备上是否找到了该 CLI。

Kaiwu 会在 `PATH`（Windows 上为 `cursor-agent.cmd`）中查找 `cursor-agent`，若未找到则回退至 `agent`。如果可执行文件安装在非常规路径，请在运行 Kaiwu CLI 或守护进程的环境中，将 `HAPPIER_CURSOR_PATH` 设置为该可执行文件的绝对路径。

## 身份验证

支持以下两种方式，Kaiwu 均可识别。

**API 密钥。** 在 Kaiwu CLI 或守护进程使用的环境中设置 `CURSOR_API_KEY`。Kaiwu 会读取该变量，但不会将其值复制到会话元数据或日志中。

**Cursor 自带登录。** 按常规方式使用 `cursor-agent` CLI 登录。Kaiwu 会运行 Cursor 自带的只读状态命令来读取缓存状态，因此 **Settings → AI & Agents → AI backends → Cursor** 能如实反映你的实际登录状态，无需通过 Kaiwu 重新认证。

该状态检查在后台运行十分安全。因此与某些智能体不同，Cursor 的登录状态会自动保持最新。

## 启动会话

```bash
happier cursor
```

或者在任意客户端的新建会话流程中，选择 **Cursor** 作为 AI 后端。

### 模型

Kaiwu 会向 Cursor 查询其提供的模型并展示列表，而不是使用容易过期的硬编码目录。选择模型后，会通过 Cursor 自身的 ACP 配置进行应用，所选即所用，由 Cursor 确认生效。

Cursor 不接受任意模型 ID，你只能从它公布的模型中进行选择。如果你需要的模型未在列表中，决定权在于 Cursor 的 CLI，而非 Kaiwu。

### 权限模式

Kaiwu 的权限模式会直接映射到真实的 `cursor-agent` 标志位，并非仅供参考的建议设置：

| Kaiwu 模式 | Cursor 启动参数 |
| --- | --- |
| 默认 | 无覆盖参数——Cursor 照常询问 |
| 接受编辑 | `--force --sandbox enabled` |
| 绕过所有权限 | `--force` |

各类智能体中各模式的具体含义，请参阅[权限](/sessions/permissions)。

## 限制

以下限制大多由 Cursor 自身的能力决定，权威的自动生成清单请参阅[智能体能力表](/agents/capabilities)。开始前建议了解以下几点：

- **图像仅支持单向传输。** Cursor 可以生成图像，并在 Kaiwu 中以持久化会话媒体的形式保存（重新加载后依然保留）。但 Kaiwu 无法向 Cursor 发送图像——该智能体暂不支持在提示词中附加截图。
- **恢复会话功能仍处于实验阶段。** Kaiwu 会保存 Cursor 会话标识，并能在提供商进程重启后请求恢复，但它会在运行时检查当前安装的 CLI 是否真正支持该操作，而非盲目假定支持。
- **不支持通过 Cursor 进行会话浏览、派生或回滚。** Kaiwu 无法列出你已有的 Cursor 会话、无法进行原生分支派生，也无法回滚对话。在 Kaiwu 提供这些操作的界面中，Cursor 相关入口会提示不可用并说明原因，而不会静默执行其他行为。Kaiwu 自身的[重放分支](/sessions/session-forking)是独立机制，不受此限制影响。
- **工具调用通过 shell 桥接运行**，该链路对 Cursor 而言仍处于实验阶段。
- **每台设备同一时间仅限一个会话。** Cursor 的本地控制具有排他性，Kaiwu 无法附加到你自己启动的 `cursor-agent` 进程上。
- **无计划模式。** Cursor 仅公开了单一会话模式。

## 高级设置

`HAPPIER_CURSOR_API_ENDPOINT` 可将 `cursor-agent` 指向非默认 API 端点。请在运行 Kaiwu CLI 或守护进程的环境中进行配置；Kaiwu 将在启动时透传该参数。

## 故障排查

### “找不到 Cursor”

1. 确认 `cursor-agent --version` 在将要运行会话的设备上能正常工作——如果会话运行在其他设备上，请不要在本地笔记本上检查。
2. 安装 CLI 后重启 Kaiwu，以便重新执行检测。
3. 如果二进制文件不在常用路径下，请将 `HAPPIER_CURSOR_PATH` 设置为其绝对路径。

### 会话启动失败或模型列表为空

1. 在 **Settings → AI & Agents → AI backends → Cursor** 下检查登录状态。
2. 若使用密钥认证，请确认 Kaiwu CLI 或守护进程的环境变量中包含 `CURSOR_API_KEY`——而不仅存在于交互式 shell 中。如果在导出环境变量前就已经启动了守护进程，它是读取不到该变量的。
3. 更新 `cursor-agent`。较旧版本的 CLI 可能会接受 ACP 连接，但不会返回可用模型清单。
