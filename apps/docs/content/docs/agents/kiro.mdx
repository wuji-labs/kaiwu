Kaiwu 支持将 **Kiro** 作为基于本地 CLI 的提供商。

Kiro 本身即为一个内置提供商，它**不同于** **Custom ACP**。

- **Kiro**：Kaiwu 专属的内置 Kiro 集成
- **Custom ACP**：面向各类兼容 ACP 的 CLI 与用户自定义后端的通用提供商体系

这意味着自定义 ACP 后端**不会**通过 Kiro 提供商路径运行。

<Callout type="info">
  Kiro 是一项**实验性**集成。它功能完备且可用于日常工作，但其接口成熟度不及 Claude、Codex 或 OpenCode，后续也更可能发生变动。当前支持的功能详见[智能体能力](/agents/capabilities)。
</Callout>

## 环境要求

- 本地已安装 Kiro CLI
- 二进制文件位于 `PATH` 路径下（或根据需要配置 `HAPPIER_KIRO_PATH`）

## 安装 Kiro

请按照 Kiro CLI 官方指南完成安装，随后进行验证：

```bash
kiro-cli --version
```

## 在 Kaiwu 中进行本地认证

Kiro 支持通过以下路径启动其原生登录流程：

- **Settings → AI & Agents → AI backends → Kiro**

在该界面中，你可以：

- 直接在 Kaiwu 内打开 `kiro-cli login`
- 点击 **Check now**，在选定设备上重新检测认证状态

目前对 Kiro 认证状态的检测策略较为保守，因此即便登录流程可用，Kaiwu 仍可能显示为 **Unknown**。

通用用户指南请参阅[提供商认证](/agents/provider-authentication)。

## Kiro 与 ACP

由于 Kiro 是内置且支持 ACP 的提供商，它也会出现在 Kaiwu 的 **ACP Backends** 设置界面中。

该界面有助于了解 ACP 后端的一般工作机制；但若只是正常使用 Kiro，你**无需**在此处进行配置。

使用原则：

- 需要使用 Kiro 本身时，请前往 **Kiro 提供商页面**
- 需要接入其他兼容 ACP 的 CLI 或创建自定义后端时，请使用 **Custom ACP / ACP Backends**

参阅：

- [Custom ACP](/agents/custom-acp)
- [Custom ACP](/agents/custom-acp)

## 注意事项

- Kiro 通过真实的 Kiro CLI 在你的设备本地运行。
- 一旦 Kiro 提供更可靠的非交互式认证信号，Kaiwu 即可在不改动登录流程的前提下展示更详尽的状态细节。

## 故障排查

若 Kaiwu 未检测到 Kiro：

1. 验证 `kiro-cli --version` 是否可正常运行。
2. 重启 Kaiwu。
3. 重新打开提供商设置页面，并点击 **Check now**。
