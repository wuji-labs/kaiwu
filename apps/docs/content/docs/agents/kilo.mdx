Kaiwu 支持将 **Kilo** 作为由本地 CLI 驱动的提供商。

<Callout type="info">
  Kilo 是一项**实验性**集成。它功能完备且已有人日常使用，但相比 Claude、Codex 或 OpenCode，其接口更新，未来也更可能发生变动。当前支持的功能详见[智能体能力清单](/agents/capabilities)。
</Callout>

## 环境要求

- 本地已安装 Kilo CLI
- `PATH` 中包含其可执行文件（或设置 `HAPPIER_KILO_PATH`）

## 安装 Kilo

在你的设备上安装 Kilo，然后重启 Kaiwu：

```bash
npm install -g @kilocode/cli@latest
kilo --version
```

Kaiwu 也可以为你自动安装：

```bash
happier install provider kilo
kilo --version
```

## 在 Kaiwu 中进行本地认证

Kilo 支持从以下路径调起其原生登录流程：

- **设置 → AI 与智能体 → AI 后端 → Kilo**

在此页面中，你可以：

- 直接在 Kaiwu 内打开 Kilo 并启动 `/connect` 流程
- 点击**立即检测**，重新检测所选设备上的认证状态

当前对 Kilo 的认证状态检测策略偏保守。Kaiwu 可以打开登录流程；但若 Kilo 未暴露安全的非交互式本地认证信号，界面仍可能显示为**未知**。

通用使用指南请参见[提供商认证](/agents/provider-authentication)。

## 在 Kaiwu 中启用 Kilo（实验性）

Kilo 目前属于 Kaiwu 的实验性提供商功能。

在应用内：

1. **设置**
2. **AI 与智能体 → AI 后端**
3. **Kilo（实验性）**

## 说明

- Kilo 通过真实的 Kilo CLI 在你的设备本地运行。
- 会话恢复、模型、模式和权限等会话能力均由能力机制动态驱动，并随所安装的运行时版本演进。
- 如遇疑问，请以 Kilo 自身的 CLI 配置作为提供商原生行为的基准。

## 故障排查

### “Kilo not found”

- 确认已安装 Kilo：`kilo --version`
- 安装完成后重启 Kaiwu。
- 若 PATH 中未包含 Kilo，请将 `HAPPIER_KILO_PATH` 设置为 `kilo` 可执行文件的绝对路径。

### “Not authenticated”

前往 Kaiwu 中的 Kilo 提供商设置页面，或在终端运行 Kilo 常规的本地登录流程，随后点击**立即检测**。
