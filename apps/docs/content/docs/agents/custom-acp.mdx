**Custom ACP** 是 Kaiwu 的通用提供商系列，面向所有支持 Agent Client Protocol（ACP）的 CLI。

如果 Kaiwu 没有为您想运行的工具提供专用的内置提供商，或者您希望基于兼容 ACP 的 CLI 添加自定义后端选项，均可使用该功能。

<Callout type="info">
  Custom ACP 是一项**实验性**集成。它功能完备，且已有用户在日常使用，但其对外接口比 Claude、Codex 或 OpenCode 更年轻，未来调整的可能性也更大。当前支持的功能详见[智能体能力](/agents/capabilities)。
</Callout>

## Custom ACP 提供的内容

通过 Custom ACP，您可以定义**自定义 ACP 后端**。

每个自定义 ACP 后端都兼具双重属性：

- 它是兼容 ACP 的 CLI 启动器定义
- 它是可在整个 Kaiwu 中随时选择的面向用户的后端选项

## 功能入口

打开 **Settings → AI & Agents → AI backends**，向下滚动越过内置智能体列表。该界面底部包含两个分组：

- **Built-in ACP**——Kaiwu 自带的通用 ACP 智能体，定义在共享目录中，并通过共享 ACP 运行时执行。
- **Custom backends**——您自定义的后端。每个后端都是一个可选的兼容 ACP 的 CLI 定义，拥有专属的启动器、默认值和认证设置。

点击 **Add ACP backend** 即可新建后端。

<Callout type="info">
  Custom ACP 并不是后端列表中的某一行，而是该列表下方的一个独立分组。很多用户之所以误以为该功能缺失，通常是因为在 Claude、Codex 等列表中寻找它。
</Callout>

## 自定义 ACP 后端包含的内容

自定义 ACP 后端存储了 Kaiwu 启动和处理某个后端选项所需的全部信息。

常见的后端配置项包括：

- id / 名称 / 标题
- 描述
- 命令
- 参数
- 环境变量
- 传输配置文件
- 认证元数据
- 能力提示
- 可选的默认模式
- 可选的默认模型

## Custom ACP 在 Kaiwu 中的呈现方式

配置完成的 ACP 后端享有与原生后端同等的一等地位。

它们会出现在以下位置：

- **新建会话**的后端选择器
- **配置文件兼容性**与特定后端的默认设置
- **权限**默认设置
- 代码审查（review）、规划（plan）和委派（delegate）等**会话启动器**流程
- 感知后端的引导与建议界面

这意味着一旦配置好后端，您就无需再死记硬背底层命令行参数。

## 模型、模式与默认设置

当底层的 ACP CLI 支持时，Kaiwu 可以直接探测已配置后端的以下信息：

- 可用模型
- 可用模式
- 其他 ACP 能力提示

这样一来，即使不同的自定义后端启动的是同一个 CLI（仅参数或环境变量不同），它们也能表现为完全独立的后端选项。

您还可以在新建会话的引擎选择器中，将 Custom ACP 模型收藏为常用项。收藏项按具体的配置后端分别存储，而非仅按提供商系列归类。

## 认证

Custom ACP 并不依赖单一的提供商级别认证系统。

相反，认证与就绪状态元数据直接归属于各个 ACP 后端定义。根据具体 CLI 的不同，后端可以声明：

- 登录命令
- 状态检查支持
- 设备登录提示
- 文档链接

部分 ACP CLI 支持安全的非交互式状态检测，而另一些实际上仅支持手动操作。

常规模型请参阅[提供商认证](/agents/provider-authentication)。

## Custom ACP 与内置提供商的区别

如果 Kaiwu 已经为该工具提供了专用集成，请直接使用内置提供商。

在以下情况下请使用 Custom ACP：

- 正在接入其他兼容 ACP 的 CLI
- 希望拥有自定义启动器、认证及默认值元数据的专属后端选项
- 希望使用通用 ACP 集成，而非定制的提供商专属页面

例如：

- 使用 [Kiro](/agents/kiro) 体验 Kaiwu 内置的 Kiro 集成
- 使用 **Custom ACP** 接入任意用户自定义的 ACP 后端

## 常见使用场景

### 单一 CLI，多个后端选项

如果您希望为同一个 CLI 提供多种变体，可以创建多个自定义 ACP 后端。

在以下情况下推荐采用这种模式：

- 执行命令大体相同
- 认证配置一致
- 各角色所需的参数、环境变量或默认值各不相同

### 团队内部的 ACP 智能体

如果您的团队开发了内部专用的兼容 ACP 的 CLI，而 Kaiwu 开箱并不支持，请使用 Custom ACP。

### 开发与测试

在开发过程中，如果您希望将 Kaiwu 指向本地 ACP stub 或测试工具，请使用 Custom ACP。

## Custom ACP 的局限性

它不会把任意 CLI 变成拥有专属定制界面的原生集成。

- 像 Kiro、Claude、Codex 和 Gemini 这样的内置智能体拥有独立的专属页面与行为逻辑。
- 自定义后端则统一经由通用 ACP 运行时路径执行。
- 支持的功能程度完全取决于您的 ACP CLI 实际暴露了哪些能力——Kaiwu 只能呈现该智能体主动声明的能力。

## 故障排查

**后端未出现在选项中。** 请检查该后端是否仍存在，是否包含有效的 id 和标题，以及命令是否仍处于配置状态。

**运行同一 CLI 的两个后端表现不一致。** 这是符合预期的。如果它们使用了不同的参数或环境变量、探测到了不同的 ACP 元数据，或者配置了不同的默认模式与模型值，表现自然会有所不同，而这也正是分开定义它们的意义所在。

**期望它能像内置智能体一样运作。** 若已有内置支持，请直接使用内置智能体——例如 [Kiro](/agents/kiro)。Custom ACP 专门用于接入 Kaiwu 未内置的后端。
