description: 在 Kaiwu 中管理设备本地提供商 CLI 认证，检查认证状态，并在应用内打开提供商登录流程。
---
Kaiwu 支持直接在各个提供商设置页面中，检查并管理受支持提供商 CLI 的**设备本地认证状态**。

该功能与[已连接服务](/accounts/connected-services)互不影响：

- **提供商认证**：安装在特定设备上的提供商 CLI 原生登录状态
- **已连接服务**：存储在 Kaiwu 中、可在兼容后端之间复用的凭据

该功能也不同于**自定义 ACP**：

- Claude、Codex、Gemini 或 Kiro 等内置提供商拥有专属的提供商页面
- 自定义 ACP 会将就绪状态与登录元数据存储在各个 ACP 后端定义内，不会为所有自定义后端暴露单一、全局的提供商级认证状态

## 入口位置

前往：

1. **设置**
2. **AI 与智能体 → AI 后端**
3. 选择一个提供商
4. 在上下文栏中选择目标设备
5. 找到**认证**区域

认证区域与具体设备绑定。切换到其他设备后，Kaiwu 将转而检查对应设备上的提供商 CLI。

## Kaiwu 显示的内容

根据提供商的不同，Kaiwu 可显示以下信息：

- **状态**——已登录、已登出或未知
- **登录身份**——在提供商安全暴露账号信息的前提下，显示账号邮箱或标签
- **方式**——例如 API 密钥、认证令牌、OAuth CLI 登录、凭据文件或 Google ADC
- **来源**——结果来自环境变量、本地文件还是提供商 CLI 命令
- **问题**——无法确认登录的原因，例如凭据缺失或凭据已过期
- **上次检查时间**——Kaiwu 上次刷新该认证状态的时间

## 可用操作

### 登录 / 重新认证

若提供商支持原生 CLI 登录流程，Kaiwu 可直接在应用内唤起。

其运行机制如下：

- 在大屏布局下，登录终端会打开于会话终端复用的底部窗格系统中
- 在手机屏幕尺寸下，Kaiwu 会采用更聚焦的终端展示形式
- Kaiwu 会在所选设备上启动提供商的真实 CLI
- 若提供商需要终端内命令（例如 `/login`、`/auth`、`/setup` 或 `/connect`），Kaiwu 会代为发送
- 若提供商输出了网址，Kaiwu 会在终端界面中提供复制/打开操作

登录流程退出后，Kaiwu 会自动刷新该提供商的认证状态。

### 立即检查

**立即检查**会强制立即刷新所选设备上对应提供商的认证状态。

适用于以下场景：

- 你在 Kaiwu 之外完成了登录，希望立即更新状态
- 你修改了环境变量
- 你想重新检查此前处于“未知”状态的项目

## “未知”代表什么

部分提供商提供了安全、非交互式的方式来确认本地认证状态，部分则没有。

若 Kaiwu 显示**未知**，通常意味着：

- 该提供商尚未暴露可靠的非交互式认证探测方式
- 提供商 CLI 检查超时或失败
- Kaiwu 在后台检测期间有意避开了交互式提供商命令

“未知”**并不**等同于“已登出”。

| --- | --- | --- |
| Claude | 支持 | 支持 |
| Codex | 支持 | 支持 |
| Gemini | 支持 | 支持 |
| OpenCode | 支持 | 支持 |
| Copilot | 支持 | 支持 |
| Augment (Auggie) | 支持 | 受限 / 保守检测 |
| Kiro | 支持 | 受限 / 保守检测 |
| Qwen | 支持 | 受限 / 保守检测 |
| Kimi | 支持 | 受限 / 保守检测 |

| Pi | Kaiwu 内无原生登录流程 | 支持，基于环境变量 |

“受限 / 保守检测”意味着 Kaiwu 可以启动登录流程，但仅在提供商暴露了安全的本地信号时，才会将认证状态报告为正常。

## 在自定义 ACP 中的工作机制

与专属提供商页面相比，自定义 ACP 更加通用。

对于自定义 ACP：

- 认证与登录提示保存在 **ACP 后端**定义中
- 不同的 ACP 后端可表现出不同的登录与状态行为

因此，在使用**自定义 ACP** 时，请从以下角度考虑：

- “该后端在此设备上是否就绪？”
- 而非“通用自定义 ACP 提供商是否存在全局登录状态？”

详见[自定义 ACP](/agents/custom-acp)。

## 登录终端与 Kaiwu 其它模块的协作

提供商登录终端并非一次性弹窗，它复用了 Kaiwu 内嵌会话终端的底层架构：

- 复用同一套连接设备的终端传输通道
- 复用网址识别以及打开/复制操作
- 在大屏布局下复用同一个底部窗格宿主
- 复用相同的关闭、重启与清屏行为

这种设计避免了引入第二套终端界面，使提供商登录流程与应用其余部分保持一致。

## 常见使用场景

### “我安装了提供商 CLI，想在应用内完成配置”

打开提供商设置页面，确认检测到 CLI，随后点击**登录**。

### “我已经在外置终端中完成登录，想让 Kaiwu 识别到”

打开提供商设置页面，点击**立即检查**。

### “我想查看设备当前使用的是哪个账号”

若提供商安全暴露了账号标签，Kaiwu 会将其显示在**登录身份**中。

### “我使用的是环境变量认证，而非交互式登录”

若提供商支持，Kaiwu 能够检测出基于环境变量的认证，并相应展示其认证方式。

## 重要限制

- 提供商认证仅在**设备本地**生效。在某台设备上登录提供商，并不会让其他设备自动登录。
- 并非所有提供商都支持可靠的非交互式认证检测。
- 已连接服务与设备本地认证可同时存在于同一个提供商下，二者解决的问题各不相同。
- 若上游变更了提供商登录流程，Kaiwu 会遵循提供商 CLI 当前的实际行为，而不会自行封装一套定制认证流程。
- 对于自定义 ACP，认证与就绪状态绑定于具体的后端，而非全局统一的提供商状态。

## 提供商认证与会话交接

该机制对**跨设备会话交接**至关重要。

将某个会话迁移至其他设备时：

- 设备本地的提供商认证不会自动同步过去
- 目标设备仍须具备运行该提供商或后端的能力

若该提供商或后端支持 Kaiwu [已连接服务](/accounts/connected-services)，这通常是让目标设备在交接时直接就绪的最简方案，无需单纯依赖该设备上的 CLI 原生登录。

若提供商或后端依赖本地原生认证，则仍须先在目标设备上完成认证。
