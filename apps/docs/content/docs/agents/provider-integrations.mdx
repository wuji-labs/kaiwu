Kaiwu 以子进程形式运行 **提供商 CLI**（例如 **Claude Code** 与 **OpenCode**），并将会话记录和状态同步到你的 Kaiwu 服务器，方便你从其他设备无缝接续。

绝大多数第三方“集成”项目都可以归入以下两类：

1) **基于环境变量**：设置类似 `ANTHROPIC_BASE_URL` / `ANTHROPIC_AUTH_TOKEN` 的环境变量。
2) **基于配置文件**：写入提供商 CLI 读取的配置文件（例如 `~/.claude/settings.json`）。

若想在 Kaiwu 中使用它们，唯一的要求是：**Kaiwu 启动的提供商 CLI 进程必须能够读取这些配置**。

这一点不仅影响常规的提供商会话，也同样适用于每个提供商设置页中的**认证**模块。因为 Kaiwu 需要通过 CLI 运行环境、本地文件或提供商原生状态命令，来读取该设备本地的提供商认证状态。

如需了解 Kaiwu 内置的面向用户的 MCP 管理功能（包括 Kaiwu 托管的 MCP 服务器、已检测到的提供商原生 MCP 配置、配置预览、JSON 导入以及按会话选择 MCP），请参阅：

- [MCP 服务器](/extending/mcp-servers)

## 环境变量如何传递给提供商进程

### 从终端启动的会话

如果直接从终端启动会话，Kaiwu 会继承当前 shell 的环境变量，并透传给提供商进程。

这意味着像 `eval "$(…)"` 这样仅导出环境变量的“激活”命令可以很好地工作：先执行激活命令，再运行 `happier` 即可。

### 从客户端 / 远程启动的会话（守护进程）

当从应用远程启动会话时，由于脱离了交互式 shell 环境，提供环境变量的最可靠方式是：

- **设置 → 配置文件**：创建或选择一个配置文件，并在其中配置相应的环境变量。

守护进程启动提供商 CLI 进程时，会自动将该配置文件中的环境变量注入其中。

关于配置文件的完整指南，请参阅[功能特性 → 配置文件](/agents/profiles)。

## Claude Code Router (`claude-code-router`)

Claude Code Router 会启动一个本地服务，并通过设置 `ANTHROPIC_BASE_URL` 和 Token 让 Claude Code 与该服务通信。

在 Kaiwu 中的推荐使用流程：

1) 安装并配置 `claude-code-router`。
2) 启动路由服务（`ccr start`）。
3) 为 Claude Code 配置环境变量：
   - 终端流程：执行路由服务的激活命令（例如 `eval "$(ccr activate)"`），然后启动 Kaiwu（`happier`）。
   - 远程 / 客户端流程：创建一个 **Claude** 配置文件，并配置：
     - `ANTHROPIC_BASE_URL` → 你的路由服务地址（例如 `http://127.0.0.1:3456`）
     - `ANTHROPIC_AUTH_TOKEN` → 路由服务的 API 密钥/Token（若已配置）

在搭配 Kaiwu 使用时，请勿使用 `ccr code …`：它会直接启动 Claude Code，从而绕过 Kaiwu 的会话同步机制。

## Claude Code Switch (`claude-code-switch`)

`claude-code-switch` 提供以下能力：

- `ccm`：输出 `export …` 语句，便于你在*当前 shell* 中切换提供商。
- `ccc`：切换提供商*并随即执行 `claude`*（快捷启动器）。
- 可选的持久化模式：在项目内的 `~/.claude/…` 和/或 `.claude/…` 下写入配置文件。

在 Kaiwu 中的推荐使用流程：

### 终端流程（基于环境变量）

1) 安装 `claude-code-switch` 并配置 API 密钥（`ccm config`）。
2) 在当前 shell 中切换提供商（示例）：
   - `eval "$(ccm glm global)"`
3) 正常启动 Kaiwu：
   - `happier`

在 Kaiwu 中**请勿**使用 `ccc …`。`ccc` 会直接启动 `claude`（绕过 Kaiwu）。正确做法应是由 Kaiwu 来生成已注入切换后环境变量的 `claude` 进程。

### 远程 / 客户端流程（配置文件）

创建一个 **Claude** 配置文件（设置 → 配置文件），并设置与 `ccm` 导出内容相同的值，例如：

- `ANTHROPIC_BASE_URL`
- `ANTHROPIC_AUTH_TOKEN`
- （可选）`ANTHROPIC_MODEL` / `ANTHROPIC_SMALL_FAST_MODEL`

随后在应用中启动会话时，选择该配置文件即可。

### 持久化模式（进阶）

如果你更倾向于让 `claude-code-switch` 写入 `~/.claude/settings.json`（用户级）或 `.claude/settings.local.json`（项目级），这种方式同样适用于 Kaiwu，因为提供商 CLI 启动时会自动读取这些文件。

若遇到提供商设置“未生效”的情况，最简单的排查手段是换回上述环境变量/配置文件方案（直观且易于调试）。

## Oh My OpenCode (`oh-my-opencode`)

`oh-my-opencode` 本质上是一个 **OpenCode 插件/配置安装器**。Kaiwu 通过 ACP（`opencode acp`）运行 OpenCode，因此通用规则如下：

- 只要你直接运行 `opencode` 时能正常调用该插件，Kaiwu 运行它时的表现就会完全一致。

在 Kaiwu 中的推荐使用流程：

1) 安装 OpenCode。
2) 安装并配置 `oh-my-opencode`（通常会更新 `~/.config/opencode/…` 下的 OpenCode 配置）。
3) 在 Kaiwu 中启动 OpenCode 会话（OpenCode 模式）。

对于远程 / 客户端会话，请确保**目标设备（即运行守护进程的设备）上已安装 OpenCode 及其插件**。
