在 Kaiwu 会话中运行的 Agent 能够启动其他会话并为其分配工作。它可以将独立的任务派发给另一台设备上的全新会话，自己继续当前工作，稍后再回头查看执行结果。

该功能默认开启。了解它的确切行为很有必要，因为我们在设计时特意将有用操作与危险操作作了隔离。

## Agent 无需许可即可执行的操作

默认允许协调与巡检类操作：创建会话、向指定会话发送消息、列出其有权查看的会话、读取这些会话的状态和历史记录，以及检索自身可用的 Agent、模型、模式、配置文件与关联服务。

设定这些默认值的代码逻辑十分明确：会话内的 Agent 默认拥有协调与巡检能力；破坏性操作、记账相关行为以及用户审批控制则必须保持默认关闭，由用户显式开启。

## 未经你允许不可执行的操作

除非你主动开启，否则会话内的 Agent 默认无法执行以下操作：

- 停止、归档或取消归档其他会话
- 代你响应权限请求或回答面向你的提问
- 裁定审批请求
- 消耗用量额度重置点数
- 更改哪个会话是主目标或跟踪目标
- 清空终端输入区
- 中断正在运行的回合以强制推入待处理消息

其核心原则是：任何消耗费用、代你决策或破坏成果的操作，都必须预先取得你的首肯。

## 唯一无法开启的限制

**子会话的权限永远无法超越创建它的父会话。** 若 Agent 申请高于自身的权限模式，系统会直接拒绝该请求，而非自动降级处理——Kaiwu 会将请求的权限模式与调用方进行比对，凡是更高的请求一律拒绝。

这并不是一项配置项。没有任何开关能让衍生的子会话获得超越父会话的自由度，这意味着自主 Agent 的影响范围始终严格受限于你当前正在查看的会话权限。

## 收紧衍生策略

打开 **Settings → Actions** 即可找到 **AI session spawn policy**。该策略仅控制会话内的助手在创建新会话时的行为边界，你本人直接创建会话不受任何影响。

共有 12 个开关用于决定新会话的哪些属性允许 Agent 自主选择而非强制继承。所有开关默认均为开启状态：

| 开关 | 允许 Agent 自主选择的属性 |
| --- | --- |
| Custom directory | 不同的工作目录 |
| Cross-machine targets | 在另一台可用设备上创建 |
| Backend target | 不同的 Agent 或后端 |
| Model | 指定模型，而非继承父会话的模型 |
| Permission mode | 更低或相等的权限——提权请求仍会被拒绝 |
| Agent mode | Agent 模式或会话模式 |
| Config options | 提供商选项，例如思考强度和工作流 |
| Profile | 通过 ID 指定配置文件，且不暴露其机密信息 |
| Environment variables | 为新会话显式指定环境变量 |
| Connected services | 关联服务绑定（通过引用方式） |
| MCP selection | 与父会话不同的一组 MCP 服务器 |
| Transcript storage | 兼容的会话记录存储模式 |

关闭某个开关并不会打断继承机制：子会话仍会沿用父会话的对应取值。变化之处在于，如果 Agent 尝试显式覆盖该属性，系统会明确报错拒绝，而不会顺应其设置。

### 权限上限

此外，你还可以额外设定一个**低于**调用方自身权限的硬性上限。默认情况下不设上限，仅以调用方自身的权限为边界。

将上限设为 **Plan** 或 **Read-only** 是最强硬实用的风控手段：它既允许 Agent 自由委托任务，又能确保衍生出的任何会话都不具备写入权限。**Accept edits**、**Safe yolo**、**Bypass permissions** 和 **Yolo** 各自允许达到对应的权限级别，*前提是调用方自身也具备该级别*——上限只能收紧权限，绝无法放宽。

## 衍生会话的呈现形式

衍生的子会话就是一个普通的 Kaiwu 会话。它会出现在你的会话列表中，同步至你的所有设备，并且你可以像对待其他任何会话一样查看、引导并停止它。Agent 创建的任何内容都不会对你隐瞒。

凡是需要你定夺的操作，都会以审批请求的形式呈现，绝不会暗中放行——参见[收件箱与审批](/sessions/inbox-and-approvals)。

## 异常排查

**Agent 提示无法创建会话。** 请先检查衍生策略：如果 Agent 尝试设置已被你关闭的项目（例如切换到其他设备、指定特定模型或配置环境变量），该请求会被拒绝，错误信息中会标明被禁用的项，而 Agent 可能会将其作为通用错误汇报。

**衍生的子会话权限低于预期。** 这是权限上限或防提权规则在正常起效。请直接调高*父*会话的权限模式或放宽权限上限，而无需去子会话中寻找设置。
