Kaiwu 将可复用的 AI 指令整合到同一个功能区中。你可以在这里使用单一的标准库，并通过多种方式应用或导出库中保存的内容。

从用户视角来看，它包含五个相互关联的模块：

1. **库（Library）**——用于同步你的提示词文档和技能包
2. **模板（Templates）**——可复用的斜杠快捷指令，用于快速插入已保存的提示词
3. **系统提示词追加项（System prompt additions）**——挂载到编程、语音以及配置文件等不同使用场景下的有序指令
4. **外部资产（External assets）**——存在于特定设备或项目中的提示词与技能
5. **注册中心（Registries）**——可安装的技能目录，例如 `skills.sh` 或 Git 源

核心原则如下：

- **以 Kaiwu 库为唯一可信源**
- 外部文件仅作为可选的导入、安装与导出对象
- Kaiwu 会记录明确的关联关系，从而主动检测配置漂移，避免静默覆盖文件

## 库

打开 **Settings → Prompts & Skills** 即可管理可复用内容。

库目前支持两种条目类型：

- **提示词（Prompts）**——Markdown 格式的文本块
- **技能（Skills）**——包含 `SKILL.md` 的打包集合，可附带配套支持文件

如果你只需要纯文本形式的可复用指令或模板，请使用提示词；如果你需要一个便携的指令集合，并希望将其完整导出为真实的技能目录，请使用技能。

### 提示词

提示词非常适合以下场景：

- 插入到输入框中的可复用指令
- 可复用的系统提示词追加项
- 面向特定配置文件或 Agent 的专项指引
- 需要跨设备同步的个人提示词片段

每个提示词都可以包含：

- 标题
- Markdown 内容
- 所属文件夹（可选）
- 标签（可选）

### 技能

技能非常适合以下场景：

- 需要以独立技能包形式分发的可复用任务指令
- 需要附带模板或参考代码等配套文件的提示词内容
- 需要安装到 `.agents/skills`、`.claude/skills`、`.opencode/skills` 或其他特定提供商目录下的资产

每个技能都可以包含：

- 标题
- `SKILL.md` 内容
- 存放在同一技能包内的配套文件
- 所属文件夹（可选）
- 标签（可选）

配套文件常用于存放：

- `SKILL.md` 中引用的模板
- 补充的 Markdown 指令
- 配置代码片段
- 其他随技能包导出的文件

## 文件夹与标签

使用**文件夹**可以在不重复创建提示词的前提下，实现轻量化的分类管理。

推荐实践：

- 按团队或工作流划分文件夹
- 按提供商或后端配置划分文件夹
- 分别建立用于存放“模板”与“系统提示词追加项”的文件夹

标签比文件夹更加轻量，适合标记：

- `coding`
- `voice`
- `review`
- `research`
- `profile`

## 模板（Kaiwu 内置斜杠指令）

模板是基于已保存提示词构建的 Kaiwu 原生斜杠快捷指令。

打开 **Settings → Prompts & Skills → Templates** 即可创建。

每个模板都会将：

- 一个**斜杠指令 Token**（如 `/review` 或 `/ship-check`）
- 映射到库中的某个**目标提示词**
- 并指定其触发行为：
  - **插入（Insert）**
  - **插入并发送（Insert and send）**

当你需要快速向输入框填入内容，又不想将其固定为系统级规则时，模板是最高效的选择。

### 模板的工作机制

在输入框中键入已保存的 Token 时：

- Kaiwu 会解析其关联的提示词
- 将提示词内容填入输入框
- 若配置了立即发送，则会自动提交内容

Kaiwu 会主动拦截与内置操作指令的冲突，因此模板 Token 不会静默覆盖核心的斜杠操作。

## 系统提示词追加项

这是面向用户的统一称谓，在底层实现中，它们被存储为有序的提示词栈。

打开路径：

- **Settings → Prompts & Skills → System prompt additions**

你可以将提示词或技能挂载到：

- **编程 Agent（Coding agent）**
- **语音 Agent（Voice agent）**
- 任意已保存的**配置文件（Profile）**

### 运行机制

系统提示词追加项具备以下特点：

- 严格保序
- 支持单独启用或禁用
- 可在多个交互场景间复用

无论是图形界面还是命令行，Kaiwu 都会采用相同的逻辑，将它们解析并追加到当前会话的系统提示词中。

这意味着：

- 无论从 App 还是 CLI 启动会话，提示词的构建逻辑完全一致
- 配置文件级与场景级的追加项能够稳定有序地组合叠加

### 推荐用法

编程追加项适合：

- 代码审查规范
- 针对特定代码仓库的代码风格约束
- 输出格式要求

语音追加项适合：

- 偏口语化的简练表达
- 适合语音朗读的文本格式
- 语音听写或无障碍辅助偏好

配置文件追加项适合：

- 针对特定环境或接口端点的规则
- 可复用的“工作环境”或“研究场景”专属指令

## 外部资产

如需查看或管理存储在实际设备上的提示词相关文件，请打开 **Settings → Prompts & Skills → External Assets**。

该界面能够自动识别当前设备；对于项目级资产，它还能识别当前的工作区。

涵盖的资产类型包括：

- 通用的 **Agent 技能（`.agents/skills`）**
- 提供商原生的技能存放目录，如 `.claude/skills` 或 `.opencode/skills`
- 提供商原生的指令存放目录，如 `.claude/commands`

### 支持的操作

- 发现指定设备上支持的外部资产
- 查看 Kaiwu 能从该设备或项目中读取到的内容
- 将外部资产导入到库中

### 何为“由 Kaiwu 托管”

当你把库中的条目导出或安装到某个设备目标时，Kaiwu 会建立一条明确的**外部关联（external link）**记录。

该记录包含：

- 该条目来源于库中的哪一项
- 目标设备与生效范围
- 外部引用标识与路径
- 用于漂移检测的摘要哈希（Digest）

正因如此，Kaiwu 才能准确判断本地副本是否依然与库保持同步。

## 将库中条目导出到设备

你可以在提示词和技能的编辑页面，将它们导出到外部目标路径。

适用于以下场景：

- 需要在磁盘上生成特定提供商原生格式的文件
- 需要在代码仓库中生成真实的技能目录
- 需要兼容其他直接读取本地文件的工具

### 安装方式：复制 vs 符号链接

对于技能等基于文件包的目标，Kaiwu 支持两种方式：

- **复制（Copy）**——在目标位置写入一份独立的副本
- **符号链接（Symlink）**——写入一份由 Kaiwu 托管的实体副本，并将目标路径软链至该副本

如果你希望后续更新更省心、每个安装目标只保留一份托管实体，请选择**符号链接**；如果你需要完全独立、脱离依赖的本地文件，请选择**复制**。

### 漂移防护

对于被修改过的外部资产，Kaiwu 绝不会执行静默覆盖。

如果导出的关联文件或目录在本地磁盘被修改：

- Kaiwu 会检测到摘要哈希不匹配
- 此时执行导出、安装或删除操作均会提示冲突并终止，而不会直接覆盖

这是有意为之的设计。虽然库与本地副本互相关联，但 Kaiwu 始终将磁盘上的改动视为严肃的外部变更，必须经过人工确认。

## 注册中心

打开 **Settings → Prompts & Skills → Registries** 即可浏览可安装的技能目录。

目前支持的注册中心形态：

- 内置的 **`skills.sh`**
- 可灵活配置的 **Git 源**
- 基于适配器扩展的未来注册中心类型

### `skills.sh`

Kaiwu 直接对接了公开的 `skills.sh` 注册中心服务，而非仅仅检索 CLI 代码仓库。

在实际使用中：

- 浏览内置的 `skills.sh` 源即可查看真实的公开技能
- 搜索功能直接调用上游 `skills.sh` 的搜索 API
- 导入或安装前，可先打开条目查看详细信息

### Git 源

你可以通过以下方式添加 Git 源：

- 代码仓库 URL
- 本地检出目录的路径

Kaiwu 会扫描这些源中的技能包，并在同一注册中心界面中呈现，体验与内置源无异。

这非常适用于：

- 团队私有的技能代码库
- 本地实验性项目
- 经过筛选的内部技能目录

## 导入、安装与导出的区别

这三个术语在 Kaiwu 中含义各异：

### 导入（Import）

将内容**引入到 Kaiwu 库中**。

例如：

- 从 `skills.sh` 导入某个技能
- 从本地设备导入已有的 `.agents/skills/foo` 目录

### 安装（Install）

从注册中心选取条目，在将其导入到库中的同时，一并安装到选定的外部设备目标中。

执行结果：

- 库中新增同步条目
- 外部设备完成安装
- Kaiwu 记录明确的外部关联

### 导出（Export）

选取库中已有的条目，将其写入外部设备的目标路径中。

执行结果：

- 基于库中现有条目，在外部设备上生成一份副本或完成安装

## 提供商支持

Kaiwu 的库模型完全独立于特定提供商，但外部资产的支持情况则取决于各提供商自身的文件组织规范。

目前的兼容情况包括：

- **Agent 技能（`.agents`）**——通用的技能标准
- **Claude**——支持本地目录规范下的指令与技能
- **OpenCode**——支持本地目录规范下的指令与技能
- **Gemini**——支持其规范下的技能存放目录
- **Copilot**——支持其规范下的技能存放目录

即使某些提供商没有稳定的外部资产格式，Kaiwu 库本身的功能也不会受到任何影响。

## 常用工作流

### 构建可复用的编程指令

1. 创建一条**提示词**
2. 按需将其归入某个文件夹
3. 将其添加到**编程 Agent 系统提示词追加项**中
4. （可选）将其绑定至特定**配置文件**

### 创建可复用的斜杠快捷指令

1. 创建一条**提示词**
2. 打开**模板**
3. 将类似 `/review` 的 Token 映射到该提示词
4. 选择**插入**或**插入并发送**

### 从 `skills.sh` 安装技能

1. 打开**注册中心**
2. 选择 **`skills.sh`**
3. 搜索或浏览所需技能
4. 查看详情
5. 选择操作：
   - 仅**导入**到库
   - **安装**（导入到库并安装到指定设备目标）

### 将技能导出至项目

1. 在库中打开该技能
2. 选择**管理外部资产**
3. 选定设备、生效范围、目标类型及安装方式
4. 确认预览无误后提交

## 核心认知

### 库优先原则

Kaiwu 的核心设计理念是：先在统一的中心管理好提示词内容，再根据需要将其分发、连接至具体的设备和提供商。

### 尊重外部物理文件

无论是你手动修改，还是其他工具改动了磁盘上的导出资产，Kaiwu 都会将其视为有效的外部变更，杜绝静默覆盖。

### 模板不等于系统提示词追加项

- **模板**影响的是在输入框中填入或发送的内容
- **系统提示词追加项**影响的是当前会话底层的系统/追加提示词

### 技能是功能包，而非纯文本

如果你的指令需要依赖其他辅助文件，请使用技能包，而不是纯文本提示词。
