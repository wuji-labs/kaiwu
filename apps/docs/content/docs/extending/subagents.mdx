一个会话不必局限于单个 Agent 执行单一任务。工作完全可以分发出去——交给 Kaiwu 管理的评审或规划运行、Claude 团队中的队友，或是提供商自主派生的任务线程——而 **Agents** 界面就是将这一切集中呈现的地方。

<Callout type="warn">
  该功能受两个开关控制，而非一个。Subagents 目前处于实验阶段，**默认处于关闭状态**；并且只有打开 **Settings → Features** 顶部的实验开关，各项实验特性的独立开关才会显示出来。如果你已开启 Subagents 却仍未看到任何内容，通常是因为总开关尚未打开。详情参见 [Feature flags](/extras/feature-flags) 中的 `execution.runs`。
</Callout>

在一个会话中，你可以包含：

- **Kaiwu 托管的 Subagent**：由 Kaiwu 启动的评审（review）、规划（plan）和分发（delegate）运行
- **Claude 团队 Agent**：在 Claude 团队内部创建的 Claude 队友
- **提供商支持的 Agent 线程**：由提供商派生、仅供监控的任务/Agent 侧链

通过 **Agents** 界面，你可以启动这些 Agent、查看其状态、重新打开其会话记录；在运行时支持的情况下，还能对它们执行操作。

启动更多 Agent 工作的方式有三种：

- **提供商原生子 Agent**：使用当前 Agent 自带的分发或并行 Agent 功能。在当前 Agent 支持该功能的情况下，常规的分发工作请求默认采用这种方式。
- **Kaiwu 托管的执行运行与子 Agent**：包括评审、规划和分发运行，Kaiwu 可对其进行枚举、路由、审批、重新打开与控制。
- **独立的 Kaiwu 会话**：属于独立的顶层会话。创建独立会话不属于常规的分发操作。

满足以下条件之一时，请使用 Kaiwu 托管的运行：用户明确要求使用 Kaiwu 托管运行、Kaiwu 分发运行或 Kaiwu 子 Agent；用户要求的其他 Agent 后端、模型提供商、模型、账号或服务无法通过原生功能满足；或者用户启用了强制要求 Kaiwu 的自定义规则。仅存在可发现的 Kaiwu 操作本身，并不意味着会自动选择此路径。

## 规划运行 vs 规划模式

这两者名称相近，实则是完全不同的两回事：

- 从 Agents 界面启动的**规划运行**（plan run）
- 当前提供商会话中的**会话模式**（session mode），例如 `plan`

当你需要一个独立的规划器或规划风格的子 Agent 并行工作时，请使用 **Start plan run**。

当你希望当前会话本身切换到提供商支持的某种模式时，请使用会话的 **Mode** 选择器。

两者的工作流截然不同：

- 规划运行会在 Agents 界面中创建一行独立的 Agent 记录
- 会话模式则会改变当前会话本身的行为方式

如果提供商不支持会话模式，Kaiwu 便不会为该会话提供模式控件。

## 如何在会话中找到 Agent

主要有两个入口：

1. **会话标头**
   - 使用会话标头中的 Agents 按钮可快速打开 Agents 界面。
   - 徽标会显示当前会话中处于活跃状态的 Agent 数量。
2. **右侧边栏 → Agents**
   - 右侧边栏设有专门的 **Agents** 选项卡。
   - 这是用于启动 Agent、监控状态和执行快捷操作的主控界面。

启动 Agent 的原始工具卡片仍会保留在会话记录中。
Agents 选项卡并**不会**替代该历史记录，而是为你提供一份实时花名册，省去回滚查找运行中 Agent 的麻烦。

## Agents 选项卡包含的内容

该选项卡分为以下几个区块：

- **LAUNCH**：从当前会话启动新 Agent 任务的操作
- **ACTIVE**：当前正在运行的 Agent
- **RECENT**：已完成、失败或被终止的 Agent

每一行都会展示对应 Agent 的核心信息：

- 名称
- 状态
- 类型
- 提供商
- 意图（若适用）
- 最新活动预览（在 Kaiwu 已加载该会话记录时显示）

点击某一行会优先在**详情面板**中打开该 Agent，方便你在不离开当前会话的情况下查看会话记录。

同样的 Agent 或运行在原本的会话记录条目中也保持可访问，因此你既可以从花名册打开详情，也可以从它最初出现在对话中的位置打开。

## Kaiwu 中的 Agent 类型

### Subagent

这类子 Agent 由 Kaiwu 自身启动。

当前预设包括：

- **Review**（评审）
- **Plan**（规划）
- **Delegate**（分发）

当满足上述 Kaiwu 路由条件之一，且你希望发起与 Kaiwu 会话关联的有界或长期运行时，可以使用它们。

各项预设的用途：

- **Review**：并行评审当前工作树或变更集
- **Plan**：在不改变当前会话模式的前提下，进行独立的规划式推理
- **Delegate**：在并行执行工作的同时，支持你进行干预指导的辅助运行

面向用户的操作行为：

- 从 **Launch Subagents** 卡片启动
- 从 Agents 列表中重新打开
- 在运行期间发送转向/后续指令消息
- 从 Agents 列表或详情视图中停止/取消运行
- 在需要底层执行运行元数据时，打开高级运行详情

### Claude 团队 Agent

在 Claude 会话中，Kaiwu 还可以将 Claude 的团队风格子 Agent 作为一等 Agent 呈现。

你可以：

- 创建 Claude 团队
- 启动新队友
- 向现有团队中增派队友
- 直接向某位队友发送消息
- 向全队广播消息
- 终止某位队友
- 删除整个团队

Claude 团队 Agent 与 Subagent 显示在同一个 Agents 花名册中，但其控制操作为 Claude 所特有。

### 提供商支持的任务侧链

部分提供商会派生任务/Agent 侧链，Kaiwu 可将其规范化为 Agent 行。

这些行主要用于：

- 监控
- 重新打开会话记录
- 了解提供商创建的辅助线程正在执行什么操作

除非提供商/运行时开放了支持的控制平面，否则它们**仅供监控**。

这意味着，即使它们作为一等行显示在 Agents 界面中，也可能不提供发送、停止或删除等操作。

## 子 Agent 会话记录的显示位置

对于受支持的 Agent 和运行，Kaiwu 支持从两个位置访问会话记录：

- **Agents** 界面
- 主会话记录中原本的**工具条目**

这适用于：

- Kaiwu 托管的执行运行（如 review / plan / delegate）
- 从 Claude Agent Teams 中呈现的 Claude 队友
- Kaiwu 可规范化为 Agent 行的提供商任务侧链

只要该行可控，无论从哪个入口打开，都会进入相同的底层会话记录/详情界面。

## 启动新的 Agent 工作

### 启动 Subagent（Launch Subagents）

当你希望 Kaiwu 启动评审、规划或分发运行，请使用 **Launch Subagents**。

启动器支持：

- 快速启动的预设意图
- 后端选择
- 权限模式选择
- 指令输入
- 需要完整启动器/详情流程时的 **Advanced…** 入口

后端选择使用的是 Kaiwu 其他模块通用的当前 Agent 目录和启动选项。请在启动时检查操作规范（action spec）并解析其选项，以确认可接受的目标、模型、配置、账号、已连接服务及字段名称。切勿依赖文档中固定的提供商/模型方案。

对于会话内 Agent 或操作启动，省略 `sessionId` 即可将运行托管在调用方会话中。若有意针对其他已授权的会话，仍支持显式指定 `sessionId`。若要创建独立的顶层会话，请使用 `session.spawn_new`；这属于独立的工作流，而非例行的分发操作。

你可以设置有界等待来观察运行状态。等待超时并非终态：运行可能仍在进行，超时既不会停止它，也不会判定其失败。仅当提供商返回的凭据明确标明原因是可重试的（例如特定类型的暂时性速率限制）时，才应重试启动；对于其他后端故障，应根据其上报的解决方案进行处理，而不是盲目重试或切换后端。

如果会话中已有 Agent，启动区块默认会保持折叠状态，以便优先展示花名册。

### 启动 Claude 团队与队友

在 Claude 会话中，侧边栏还会显示 Claude 专属的启动操作。

你可以用它们来：

- **Create team**（创建团队）
- **Launch teammate**（启动队友）

当会话中已存在 Claude 团队时，Agents 花名册中的团队分组还会提供针对该现有团队的 **Launch teammate** 直接操作。

这样一来，当你明确知道要扩展哪个团队时，就不必再退回通用的全局启动器中操作。

## 打开 Agent

在 Agents 列表中点击某个 Agent 行时：

- Kaiwu 会首先打开**详情面板**
- 会话记录将使用与应用内其他位置**相同的会话记录渲染栈**进行展示
- 视图顶部会显示一张紧凑的摘要卡片，列出 Agent 的元数据

这种一致性设计非常关键：

- 基于工具的 Agent 会话记录与普通的聚焦工具详情采用相同的会话记录组件
- Subagent 的会话记录通过相同的会话数据流进行流式传输与更新
- 如果你需要更大的空间，依然可以切换为全屏页面打开

## 向 Agent 发送消息

### Subagent

当 Subagent 正在运行时，你可以通过以下位置发送后续指令：

- 主输入框（composer），此时将该 Agent 选为接收人
- Agent 详情面板
- 完整详情页面

Kaiwu 会在底层根据运行类型采用对应的执行运行投递模式。

正在执行的运行也可以作为接收人出现在主会话输入框中，因此你不一定非要先打开详情面板。

参见：

- [Participant routing & live run messaging](/accounts/participant-routing)

### Claude 队友

对于 Claude 团队 Agent，Kaiwu 支持通过会话输入框发送路由消息。

你可以通过接收人标签将其发送给：

- **Lead**（负责人）
- 指定队友
- **Broadcast**（广播）

当前的重要限制：

- 发送给 Claude 队友的路由消息**不支持**附件
- 发送给 Claude 队友的路由消息**不支持**评审批注草稿

当你需要这些功能时，请发送常规的 Lead 消息。

常规的非路由会话消息依然照常支持 Kaiwu 附件。

参见：

- [Attachments & image previews](/apps/attachments)
- [Custom ACP](/agents/custom-acp)

## Agent 从花名册中消失的场景

Agents 花名册遵循实时控制状态，而不仅取决于历史会话记录条目。

例如：

- 正在运行的执行运行在其仍可被控制期间会持续显示；
- 停止、取消或完成后，它会移出活跃接收人生命周期；
- 被终止的 Claude 队友会从活跃接收人列表中移除。

历史会话记录条目依然保留，但接收人选择器只显示当前仍可发送消息的有效目标。

### 仅供监控的提供商侧链

如果某一行属于提供商支持的仅监控 Agent，Kaiwu 会显示其会话记录，但不会提供发送控件。

这是有意为之：保留该行是为了提供可观察性，而不是提供提供商/运行时实际上无法响应的虚假控制选项。

## UI 中的 Agent 生命周期

### 活跃（Active）vs 近期（Recent）

- **ACTIVE** 显示当前正在运行的任务
- **RECENT** 显示已完成、失败、已取消或被终止的 Agent

这让长时间运行的会话条理更加清晰，方便你把“仍需关注的内容”与“已经结束的内容”区分开来。

### Claude 队友终止

当 Claude 队友被终止时：

- 它会从活跃/可发送消息的目标中移除
- 它依然保留在 **RECENT** 中，以供追溯历史

这就避免了混淆——防止出现 Claude 已经关闭了该 Agent，而界面上看起来却依然可用的情况。

### 运行中会话记录的可观察性

你无需回滚到启动位置去监控正在运行的 Agent。

Agents 选项卡是权威的实时花名册，用于查看：

- 当前正在运行的内容
- 近期已完成的内容
- 如何重新打开对应的会话记录

## 直连会话、非活跃会话与可恢复会话

Agent 控制能力取决于你当前处于哪种会话中。

### 已同步的活跃会话

这类会话支持完整的 Agent 控制界面。

### 非活跃但可恢复的会话

如果会话处于非活跃状态**但可恢复**，且设备可访问：

- Kaiwu 依然可以展示 Kaiwu-subagent 启动器
- 启动 Subagent 时会先恢复该会话，随后再启动子 Agent

这保证了 UI 的行为真实可靠：只要 Kaiwu 提供了启动器，启动流程就应当能够跑通。

### 已关联的直连会话

已关联的直连会话则有所不同。

如果直连会话仅处于被观察状态，且本地 runner **尚未**激活：

- 对 Subagent 而言，Kaiwu 会将其视为**仅可观察**
- 无法启动 Kaiwu-subagent
- 不提供执行运行的发送/停止控件
- 无法将执行运行选为接收人

一旦直连会话重新受本地控制，这些控制功能便会恢复可用。

## 推荐工作流

### 我希望从当前会话发起 Kaiwu 托管的并行评审

打开 **Agents** → **Launch Subagents** → **Review**。

当你希望在不丢失主会话上下文的前提下进行有界的评审流程时，请使用该方式。

### 我需要一个支持干预指导的 Kaiwu 托管辅助 Agent

启动分发（delegate）风格的 Subagent，随后在该行或详情面板中对其运行过程进行持续引导。

### 我希望 Claude 队友并行协同工作

在 Claude 会话中：

1. 创建团队
2. 启动一名或多名队友
3. 从主输入框向特定队友发送消息或进行广播

### 我仅希望监控提供商创建的辅助工作

将 Agents 选项卡用作提供商任务侧链的只读花名册。

当提供商派生了辅助线程、却未通过 Kaiwu 暴露受支持的控制界面时，这种方式非常有用。

## 心智模型

理解该功能最简单的方式是：

- **会话记录**（transcript）保留了 Agent 启动过程的因果历史
- **Agents 选项卡**是当前所有 Agent 的实时花名册
- **详情面板**是重新打开并与对应 Agent 交互的最快途径

只要理清这三者的分工，即便在包含大量 Agent 的长会话中，界面的交互逻辑依然清晰可控。
